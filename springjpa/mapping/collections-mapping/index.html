Collections: Bag, Set, List with Order, Map and @ElementCollection

Collection mappings decide how many SQL statements a single add or remove produces. Wrong choices delete and reinsert whole tables. This page shows what Hibernate does for each collection type.

Collection types and their SQL behavior

Java typeHibernate modelRemove one elementNotes
List without order columnBagIn a join table: delete ALL rows and reinsert the rest. For OneToMany with mappedBy: one DELETE (orphanRemoval)Allows duplicates. Cannot fetch two bags at once (MultipleBagFetchException)
SetSetDELETE of that row onlyNo duplicates, needs correct equals and hashCode. Best for ManyToMany
List + @OrderColumnIndexed listDELETE plus UPDATE of the index of all following elementsKeeps position in the database
List/Set + @OrderByOrdered by a column at load timeAs aboveOrder is only applied when loading
Map<K, V>Map with @MapKey / @MapKeyColumnDELETE of that entryKey stored in a column
SortedSet + @SortNaturalSorted in memoryAs SetSorting is done in Java

@OneToMany with order

@OneToMany(mappedBy = "order", cascade = CascadeType.ALL, orphanRemoval = true)
@OrderBy("lineNo ASC")
private List<OrderLine> lines = new ArrayList<>();
// SELECT ... FROM order_line WHERE order_id = ? ORDER BY line_no

@ElementCollection
@CollectionTable(name = "order_notes", joinColumns = @JoinColumn(name = "order_id"))
@OrderColumn(name = "position")
@Column(name = "note", length = 500)
private List<String> notes = new ArrayList<>();

@ElementCollection: collections of simple values or embeddables

@Entity
public class Product {
    @Id @GeneratedValue private Long id;

    @ElementCollection
    @CollectionTable(name = "product_tags", joinColumns = @JoinColumn(name = "product_id"))
    @Column(name = "tag", length = 40)
    private Set<String> tags = new HashSet<>();

    @ElementCollection
    @CollectionTable(name = "product_attributes", joinColumns = @JoinColumn(name = "product_id"))
    @MapKeyColumn(name = "attr_name", length = 60)
    @Column(name = "attr_value", length = 200)
    private Map<String, String> attributes = new HashMap<>();
}
  • Element collections have no id and no own entity. Hibernate cannot update a single row: with a List or bag it deletes and reinserts all rows of that parent when anything changes.
  • Use a Set of embeddables or a real entity with an id when the collection is large or changes often.
  • They are always owned by the parent: no cascade settings, removed with the parent.

Lazy collections and PersistentBag

product.getTags()  returns a Hibernate PersistentSet (a wrapper, not a HashSet)
   ├─ not initialized: only holds the owner and the role. No SQL yet
   ├─ first access (size(), iterator(), contains ...) ─► SELECT tag FROM product_tags WHERE product_id = ?   (needs an open session)
   └─ after the session closed ─► LazyInitializationException
Do not replace the collection object (product.setTags(new HashSet<>(...))) on a managed entity: with orphanRemoval this throws
"A collection with cascade all-delete-orphan was no longer referenced". Modify the existing collection: clear() and addAll().
// WRONG for orphanRemoval collections
order.setLines(newLines);

// RIGHT
order.getLines().clear();
order.getLines().addAll(newLines);

Avoid loading a big collection to count or add

// bad: order.getLines().size() loads all lines
// good:
long count = orderLineRepository.countByOrderId(orderId);

// @LazyCollection(LazyCollectionOption.EXTRA) lets size() run "select count(*)" (Hibernate specific)
// Adding one line: save a new OrderLine with getReferenceById(orderId), do not touch order.getLines()

MultipleBagFetchException

// FAILS: two Lists fetched in one query
@Query("select o from OrderEntity o join fetch o.lines join fetch o.payments")
List<OrderEntity> loadAll();      // MultipleBagFetchException: cannot simultaneously fetch multiple bags

// Fixes: 1. use Set for the collections   2. fetch one collection per query (the second query hits the persistence context)
List<OrderEntity> orders = repo.findWithLines();        // join fetch lines
orders = repo.findWithPayments(orders);                  // select o ... join fetch o.payments where o in :orders
// 3. hibernate.default_batch_fetch_size to load the second collection in batches

Common mistake: Replacing the collection instance of a managed entity with orphanRemoval enabled. Hibernate loses track of the original collection and fails. Always modify the existing collection with clear, add and remove.

Interview questions

When should I use @ElementCollection?

For small collections of simple values or value objects that belong completely to one entity (tags, phone numbers). For larger or independent data use a real entity.

Why did removing one element delete and reinsert all rows?

The collection is a bag (List without order column) or an element collection without an id. Use a Set, or model the rows as an entity.

How do I fetch two collections without MultipleBagFetchException?

Use Set instead of List, load them in separate queries, or use batch fetching.

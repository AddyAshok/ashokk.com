Embeddables, @MappedSuperclass and Inheritance Strategies

Reuse fields with embeddables and mapped superclasses, and choose an inheritance strategy for class hierarchies. Each choice has a different table layout, query cost and constraints.

@Embeddable: value objects inside an entity

@Embeddable
public class Address {
    private String street;
    private String city;
    @Column(name = "zip_code", length = 10) private String zipCode;
    protected Address() { }
    public Address(String street, String city, String zipCode) { this.street = street; this.city = city; this.zipCode = zipCode; }
}

@Entity
public class Customer {
    @Id @GeneratedValue private Long id;

    @Embedded private Address billing;

    @Embedded
    @AttributeOverrides({
        @AttributeOverride(name = "street",  column = @Column(name = "ship_street")),
        @AttributeOverride(name = "city",    column = @Column(name = "ship_city")),
        @AttributeOverride(name = "zipCode", column = @Column(name = "ship_zip")) })
    private Address shipping;                        // the same class twice, with different column names
}
// One table: customer(id, street, city, zip_code, ship_street, ship_city, ship_zip). No id and no separate lifecycle.
// If ALL embedded columns are null, Hibernate loads the embedded object as null.

@MappedSuperclass: share fields, no table

@MappedSuperclass
public abstract class BaseEntity {
    @Id @GeneratedValue(strategy = GenerationType.SEQUENCE) private Long id;
    @Version private Long version;
    @CreationTimestamp @Column(updatable = false) private Instant createdAt;
    @UpdateTimestamp private Instant updatedAt;

    @Override public boolean equals(Object o) { return this == o || (o instanceof BaseEntity b && id != null && id.equals(b.id)); }
    @Override public int hashCode() { return getClass().hashCode(); }
}

@Entity public class Product extends BaseEntity { private String name; }
@Entity public class Customer extends BaseEntity { private String email; }
// Every entity gets id, version and timestamps. BaseEntity cannot be queried or used in a relationship.

@Entity
@Inheritance(strategy = InheritanceType.SINGLE_TABLE)              // default
@DiscriminatorColumn(name = "payment_type", discriminatorType = DiscriminatorType.STRING)
public abstract class Payment {
    @Id @GeneratedValue private Long id;
    private BigDecimal amount;
}

@Entity @DiscriminatorValue("CARD")
public class CardPayment extends Payment { private String cardLast4; }

@Entity @DiscriminatorValue("UPI")
public class UpiPayment extends Payment { private String vpa; }

// polymorphic query: all payments (any subtype)           select p from Payment p
// only one type:                                           select p from CardPayment p
// filter by type in JPQL:                                  select p from Payment p where type(p) = CardPayment

SINGLE_TABLEFastest (no joins), simple queriesSubclass columns must be nullable, wide sparse table, no NOT NULL constraints for subclass fieldsFew subclasses with few extra fields (default choice)
JOINEDNormalized, NOT NULL constraints possibleJoins on every query, slower inserts (several tables)Many subclass fields, data integrity matters

@MappedSuperclassSimple reuseParent is not an entity: no polymorphic queries or relations to itShared audit and id fields
  • Prefer composition over deep hierarchies. A payment with a type column and a JSON or embedded detail is often simpler than five subclasses.
  • Relations to abstract parents (ManyToOne Payment) work with SINGLE_TABLE and JOINED.
  • Loading a lazy ManyToOne to a hierarchy returns a proxy of the PARENT class, so instanceof CardPayment fails. Use Hibernate.unproxy(x) or the visitor pattern.

Common mistake: Using SINGLE_TABLE with many subclasses and expecting NOT NULL constraints. All subclass columns must allow null, so the database cannot protect your data. Use JOINED or a different model when constraints matter.

Interview questions

@Embeddable or a separate entity?

Use an embeddable for a value object that has no identity and lives and dies with its owner (address, money). Use an entity when it has its own id, lifecycle or is shared.

What is the default inheritance strategy?

SINGLE_TABLE with a DTYPE discriminator column.

Why does instanceof fail on a lazy relation to a subclass?

The proxy is a subclass of the declared parent type, not of the real subtype. Unproxy the object or avoid type checks.

Setup and Configuration: Every Important Property Explained

Getting JPA running takes minutes, but the configuration properties decide performance and safety. This page lists the dependencies, the properties you will use, how Spring Boot names tables and columns, and how to see the SQL and the bound parameters.

Dependencies

<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-data-jpa</artifactId>     <!-- Spring Data JPA + Hibernate + HikariCP + spring-tx -->
</dependency>
<dependency>
    <groupId>org.postgresql</groupId>
    <artifactId>postgresql</artifactId>
    <scope>runtime</scope>
</dependency>
<dependency>                                                     <!-- optional: in-memory database for development and tests -->
    <groupId>com.h2database</groupId>
    <artifactId>h2</artifactId>
    <scope>runtime</scope>
</dependency>

Recommended application.yml

spring:
  datasource:
    url: jdbc:postgresql://localhost:5432/shop
    username: app
    password: ${DB_PASSWORD}
    hikari:
      maximum-pool-size: 10
  jpa:
    open-in-view: false                       # do not keep the session open during view rendering
    hibernate:
      ddl-auto: validate                      # Flyway changes the schema, Hibernate only checks it
    properties:
      hibernate:
        format_sql: true
        jdbc.batch_size: 50
        order_inserts: true
        order_updates: true
        default_batch_fetch_size: 50
        query.in_clause_parameter_padding: true
        jdbc.time_zone: UTC
logging:
  level:
    org.hibernate.SQL: DEBUG                  # the SQL text
    org.hibernate.orm.jdbc.bind: TRACE        # bound parameter values (Hibernate 6)
PropertyMeaningAdvice
spring.jpa.hibernate.ddl-autonone, validate, update, create, create-drop: what Hibernate does with the schema at startupvalidate or none in production. create-drop only for tests
spring.jpa.show-sqlPrint SQL to standard outputPrefer the logger org.hibernate.SQL (goes through your logging setup)
spring.jpa.open-in-viewKeep the EntityManager open until the response is rendered (default TRUE)Set false. Otherwise lazy loading works in controllers and hides N+1 and holds connections
spring.jpa.properties.hibernate.jdbc.batch_sizeStatements grouped in one JDBC batch20 to 100 for write heavy code
hibernate.order_inserts / order_updatesSort statements so equal ones can be batchedtrue when batching
hibernate.default_batch_fetch_sizeLoad lazy associations for many parents in one query16 to 100, a cheap N+1 defense
hibernate.query.in_clause_parameter_paddingPads IN lists to powers of two to reuse query planstrue
spring.jpa.database-platformDialectNot needed with Hibernate 6: it detects the dialect from the driver
hibernate.generate_statisticsCollect counts (statements, cache hits)Development and tests
spring.jpa.defer-datasource-initializationRun data.sql after Hibernate creates the schemaOnly for demos

What ddl-auto does

ValueEffectUse
noneNothingProduction with migrations
validateCompares entities with the schema and fails at startup on differences (missing table or column, wrong type)Production with Flyway/Liquibase
updateAdds missing tables and columns. Never drops or renamesPrototype only: cannot rename, no history, no data changes
createDrops and recreates at startupIntegration tests
create-dropcreate at startup, drop at shutdownEmbedded test databases

Table and column naming

Java                          Spring Boot default naming (CamelCaseToUnderscoresNamingStrategy)
class ProductCategory    ─►   table product_category
field createdAt          ─►   column created_at
@Table(name = "Products")      ─►   table products      (the naming strategy still lowercases and converts)
Change it:  spring.jpa.hibernate.naming.physical-strategy=org.hibernate.boot.model.naming.PhysicalNamingStrategyStandardImpl   (exact names)
Reserved words: an entity named Order or User breaks SQL on many databases ("order" is a keyword). Use @Table(name = "orders").

Where your entities are found

@SpringBootApplication                        // @EntityScan and @EnableJpaRepositories default to the package of this class and below
public class ShopApplication { }

@EntityScan("com.example.shop.domain")           // only when entities live outside the main package
@EnableJpaRepositories("com.example.shop.persistence")
class JpaConfig { }

Common mistake: Leaving spring.jpa.open-in-view at its default (true) and ddl-auto=update in production. The first hides N+1 problems and holds database connections while rendering, the second changes your schema silently. Set open-in-view false and use validate with migrations.

Interview questions

Why does Boot log a warning about open-in-view at startup?

Because it is enabled by default, and it keeps the EntityManager open for the whole web request, which allows lazy loading in controllers and views but can hurt scalability.

Do I need to set the Hibernate dialect?

No. Hibernate 6 detects it from the JDBC connection metadata. Set it only for special versions or to force behavior.

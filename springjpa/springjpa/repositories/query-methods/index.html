Query Methods: Derived Queries, @Query, Native, Named and Modifying

Spring Data can create queries from method names, from JPQL or SQL strings, or from named queries. This page covers every kind, all return types, parameters, SpEL, hints and the traps of modifying queries.

public interface ProductRepository extends JpaRepository<Product, Long> {

    Optional<Product> findBySku(String sku);                                        // Optional: max one result
    List<Product> findByCategoryAndPriceGreaterThanOrderByPriceDesc(String category, BigDecimal min);
    List<Product> findByNameContainingIgnoreCase(String text);
    List<Product> findByCategoryIn(Collection<String> categories);
    List<Product> findTop5ByStatusOrderByCreatedAtDesc(ProductStatus status);
    boolean existsBySku(String sku);
    long countByCategory(String category);
    List<Product> findByCustomer_Address_City(String city);                         // nested property with joins
    Stream<Product> streamByCategory(String category);                              // needs an open transaction, close it!
    void deleteByStatus(ProductStatus status);                                      // loads entities, deletes one by one
    CompletableFuture<List<Product>> findByCategory(String category, Pageable p);   // needs @Async
}

@Query with JPQL

@Query("select p from Product p where p.category = :category and p.price between :min and :max order by p.price")
List<Product> inRange(@Param("category") String category, @Param("min") BigDecimal min, @Param("max") BigDecimal max);

@Query("select p from Product p left join fetch p.tags where p.id = :id")                // fetch join
Optional<Product> findWithTags(@Param("id") Long id);

@Query("select new com.example.dto.CategoryStat(p.category, count(p), avg(p.price)) from Product p group by p.category")
List<CategoryStat> stats();

@Query("select p from Product p where lower(p.name) like lower(concat('%', :text, '%'))")   // safe: parameter is bound
List<Product> search(@Param("text") String text);

@Query("select p from Product p where p.owner = ?#{principal.username}")                  // SpEL with Spring Security extension bean

Native queries

@Query(value = "select * from products where category = :category order by price limit 5", nativeQuery = true)
List<Product> topFiveNative(@Param("category") String category);

// Paging a native query needs an explicit count query
@Query(value = "select * from products where category = :c", countQuery = "select count(*) from products where category = :c", nativeQuery = true)
Page<Product> pageNative(@Param("c") String c, Pageable pageable);

// interface projection with a native query: aliases must match getter names
interface NameAndPrice { String getName(); BigDecimal getPrice(); }
@Query(value = "select name as name, price as price from products", nativeQuery = true)
List<NameAndPrice> namesAndPrices();

Modifying queries

@Modifying(clearAutomatically = true, flushAutomatically = true)
@Query("update Product p set p.price = p.price * :factor where p.category = :category")
int raisePrices(@Param("category") String category, @Param("factor") BigDecimal factor);   // needs a transaction (add @Transactional in the service)

@Modifying
@Query("delete from Product p where p.status = 'ARCHIVED' and p.updatedAt < :before")
int purge(@Param("before") Instant before);
  • A bulk update or delete goes STRAIGHT to the database. Entities already loaded in the persistence context still hold the old values, and version columns are not incremented.
  • flushAutomatically = true flushes pending changes BEFORE the query. clearAutomatically = true clears the persistence context AFTER it, so you do not read stale entities.
  • Bulk queries skip cascades, callbacks and orphan removal.

Named queries, hints, entity graphs

@Entity
@NamedQuery(name = "Product.findExpensive", query = "select p from Product p where p.price > :limit")
public class Product { }

public interface ProductRepository extends JpaRepository<Product, Long> {
    List<Product> findExpensive(@Param("limit") BigDecimal limit);          // method name = Product.findExpensive

    @QueryHints({ @QueryHint(name = "org.hibernate.readOnly", value = "true"),          // no dirty checking for the result
                  @QueryHint(name = "jakarta.persistence.query.timeout", value = "3000"),
                  @QueryHint(name = "org.hibernate.fetchSize", value = "500") })
    List<Product> findByCategory(String category);

    @EntityGraph(attributePaths = { "tags", "supplier" })                    // fetch join without writing JPQL
    List<Product> findByStatus(ProductStatus status);

    @Lock(LockModeType.PESSIMISTIC_WRITE)                                    // select ... for update
    Optional<Product> findWithLockById(Long id);
}

Parameters

StyleExampleNote
Positional?1, ?2Fragile when you reorder parameters
Named:category with @ParamRecommended (Boot compiles with -parameters, so @Param is optional)
Collectionin :idsLarge lists: split, or use a temp table. hibernate.query.in_clause_parameter_padding helps the plan cache
Like patternsconcat('%', :t, '%')Escape % and _ from user input if literal matching is required
Pageable / SortMethod parameterSort is appended to JPQL: only allow known property names

Common mistake: Building the sort from a user string in a native query or with unchecked property names. Sort by user input opens injection paths (order by expressions). Allow only a fixed set of sortable fields.

Interview questions

Why does a derived delete run many DELETE statements?

deleteBy... loads all matching entities first and deletes them one by one (to honor cascades and callbacks). For bulk deletion write a @Modifying @Query.

Why do I still see old values after my @Modifying query?

The persistence context still holds the previously loaded entities. Use clearAutomatically = true or reload the entities in a new transaction.

Page or Slice?

Page runs an extra count query, which can be expensive on big tables. Use Slice (or Window) when you only need to know whether a next page exists.

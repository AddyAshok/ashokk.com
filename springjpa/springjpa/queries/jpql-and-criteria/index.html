JPQL and Criteria API in Depth

JPQL queries entities and their fields, not tables and columns. Learn its full syntax, joins and fetch joins, aggregates, subqueries, functions, constructor expressions, and its type-safe alternative, the Criteria API with the metamodel.

JPQL basics

// entities and attributes, not tables and columns
select p from Product p where p.price > :min order by p.name
select p.name, p.price from Product p                                  // Object[] rows or a projection
select new com.example.ProductView(p.name, p.price) from Product p      // DTO through the constructor
select count(p), avg(p.price), max(p.price) from Product p group by p.category having count(p) > 5
select distinct p.category from Product p
select p from Product p where p.name like :pattern and p.status in (:statuses)
select p from Product p where p.deletedAt is null and p.tags is not empty
select p from Product p where p.price between 10 and 50
select case when p.stock = 0 then 'OUT' when p.stock < 5 then 'LOW' else 'OK' end from Product p
select coalesce(p.discount, 0), upper(p.name), length(p.name), substring(p.name, 1, 3), concat(p.name, '-', p.sku) from Product p
select p from Product p where p.createdAt > current_timestamp - 7 day      // Hibernate 6 date arithmetic

Joins

JoinJPQLMeaning
Inner joinselect o from OrderEntity o join o.customer c where c.city = 'Pune'Only orders that have a customer
Left joinselect c, o from Customer c left join c.orders oCustomers without orders included (o is null)
Fetch joinselect o from OrderEntity o join fetch o.customerLoads the association into the entity in the SAME query (not a filter)
Join with ONselect c from Customer c left join c.orders o on o.status = 'PAID'Extra condition on the join
Unrelated entities (Hibernate 5.1+/JPA 2.1)select o, p from OrderEntity o join Product p on o.sku = p.skuJoin without a mapped relation
// Fetch join vs normal join
select o from OrderEntity o join o.customer c where c.city = 'Pune'
   // the customers are used for filtering only: o.getCustomer() is still a lazy proxy => N+1 later
select o from OrderEntity o join fetch o.customer c where c.city = 'Pune'
   // one query, customer is initialized. Use an ALIAS on a fetch join only for a filter, never to filter a fetched COLLECTION (partial collections)

Subqueries and EXISTS

select c from Customer c where exists (select 1 from OrderEntity o where o.customer = c and o.total > 1000)
select p from Product p where p.price > (select avg(x.price) from Product x)
select c from Customer c where c.id in (select o.customer.id from OrderEntity o where o.status = 'PAID')
select c from Customer c where size(c.orders) > 3            // generates a correlated count subquery
select c from Customer c where not exists (select 1 from OrderEntity o where o.customer = c)

Prefer EXISTS over joining a collection for filtering: a join multiplies rows and needs distinct, while EXISTS stops at the first match.

Running queries with the EntityManager

TypedQuery<Product> q = em.createQuery("select p from Product p where p.category = :c", Product.class);
q.setParameter("c", "books");
q.setFirstResult(40).setMaxResults(20);                                  // paging: limit/offset in SQL
q.setHint("org.hibernate.readOnly", true);
q.setFlushMode(FlushModeType.COMMIT);
List<Product> list = q.getResultList();
Product one = q.getSingleResult();                                       // NoResultException / NonUniqueResultException are thrown for 0 or 2+ rows

em.createQuery("update Product p set p.price = p.price * 1.1 where p.category = :c").setParameter("c", "books").executeUpdate();

Criteria API with the metamodel (type safe)

CriteriaBuilder cb = em.getCriteriaBuilder();
CriteriaQuery<Product> cq = cb.createQuery(Product.class);
Root<Product> p = cq.from(Product.class);

List<Predicate> where = new ArrayList<>();
where.add(cb.equal(p.get(Product_.category), "books"));
where.add(cb.greaterThan(p.get(Product_.price), new BigDecimal("100")));
if (text != null) where.add(cb.like(cb.lower(p.get(Product_.name)), "%" + text.toLowerCase() + "%"));

cq.select(p).where(cb.and(where.toArray(Predicate[]::new))).orderBy(cb.desc(p.get(Product_.price)));
List<Product> result = em.createQuery(cq).setMaxResults(50).getResultList();

// join, group, aggregate, tuple
CriteriaQuery<Tuple> t = cb.createTupleQuery();
Root<OrderEntity> o = t.from(OrderEntity.class);
Join<OrderEntity, Customer> c = o.join(OrderEntity_.customer);
t.multiselect(c.get(Customer_.name).alias("customer"), cb.sum(o.get(OrderEntity_.total)).alias("total"))
 .groupBy(c.get(Customer_.name)).having(cb.gt(cb.sum(o.get(OrderEntity_.total)), 1000));

Hibernate 6 HQL extras

select p from Product p order by p.price desc limit 10                 // LIMIT/OFFSET in HQL
select p.category, count(*) filter (where p.stock = 0) from Product p group by p.category    // FILTER clause
select cast(p.price as integer), format(p.createdAt as 'yyyy-MM') from Product p
select p from Product p where p.name ilike :name                                  // case insensitive like
select p from Product p where p.category in :categories                            // collection parameter
with recent as (select o from OrderEntity o where o.createdAt > :d) select r from recent r      // CTE (Hibernate 6.1+)
insert into ProductArchive (id, name) select p.id, p.name from Product p where p.status = 'ARCHIVED'   // insert ... select

Common mistake: Writing IS NULL tricks like (:name is null or p.name = :name) for many optional filters. It disables index use, produces poor query plans and hides intent. Build the query with a Specification or Criteria so only present filters are added.

Interview questions

What is the difference between join and join fetch?

A plain join is used to filter or select. A fetch join also initializes the association of the returned entity in the same query, which avoids lazy loading later.

Why do I get duplicate parents from a join on a collection?

A join returns one row per child. Use distinct (Hibernate 6 removes duplicate entities automatically for fetch joins) or EXISTS.

JPQL keywords are case insensitive, but what is case sensitive?

Entity and attribute names. The alias and names must match your Java classes and fields.

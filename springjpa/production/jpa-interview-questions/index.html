JPA, Hibernate and Spring Data JPA Interview Questions

The most asked questions for experienced developers, with precise answers. Every answer points to the concept explained in the course.

Basics

QuestionAnswer
JPA vs Hibernate vs Spring Data JPA?JPA is the standard API. Hibernate implements it. Spring Data JPA generates repositories on top of JPA and Hibernate.
What is an EntityManager?The JPA API for persistence operations. Its state is the persistence context (a first level cache). It is not thread safe. Spring injects a shared proxy that delegates to the transaction-bound one.
What is the persistence context?A per-EntityManager identity map of managed entities with snapshots for dirty checking. One row is one object per context.
Entity states?Transient, managed, detached, removed.
persist vs merge vs save?persist makes a new object managed. merge copies detached state into a managed instance and returns it. save calls persist if new, else merge.
What is dirty checking?At flush Hibernate compares managed entities with their snapshot and writes UPDATEs for differences, without a save call.
When does flush happen?Before commit, before queries that could be affected (AUTO), and on explicit flush().
Why is the no-arg constructor required?Hibernate creates entities by reflection and proxies as subclasses.

Mapping

QuestionAnswer
Which side owns a relationship?The side with the foreign key (@JoinColumn), the one without mappedBy.
LAZY vs EAGER defaults?ToOne is EAGER, collections are LAZY. Always set ToOne to LAZY.
Why prefer SEQUENCE over IDENTITY?IDENTITY forces immediate INSERTs and disables JDBC batch inserts. SEQUENCE with a pooled optimizer allows batching.
equals/hashCode for entities?Base on a business key or the id with a constant hashCode. Never on all fields or lazy collections.
Inheritance strategies?SINGLE_TABLE (fast, nullable columns), JOINED (normalized, joins), TABLE_PER_CLASS (UNION, avoid).
EnumType.STRING or ORDINAL?STRING. ORDINAL breaks when constants are reordered.
@Embeddable vs entity?Embeddable has no identity and shares the owner's table. An entity has its own id and lifecycle.

Queries and repositories

QuestionAnswer
How do derived queries work?PartTree parses the method name at startup into a JPA query. Wrong names fail the startup.
How does Spring Data create repository implementations?JpaRepositoryFactoryBean builds a JDK proxy over SimpleJpaRepository with interceptors for transactions, exception translation and query methods.
Page vs Slice?Page runs a count query. Slice only knows whether a next page exists.
Why is offset pagination slow?The database scans and skips all preceding rows. Use keyset pagination (Window).
What is a projection?Loading only selected columns into interfaces, records or DTOs, skipping entity management.
Specification vs @Query?Specifications compose optional filters at runtime. Use @Query for fixed queries.
What does @Modifying do?Marks an update or delete query. It bypasses the persistence context, so use clearAutomatically and flushAutomatically.

Performance and concurrency

QuestionAnswer
What is the N+1 problem and the fixes?One query for parents plus one per parent for an association. Fix with join fetch, entity graph, batch fetching, subselect or projections.
Why does join fetch with paging warn?Collection fetch with limit is applied in memory (HHH90003004). Page ids first.
How do you fix LazyInitializationException?Fetch what you need inside the transaction and return DTOs. Do not use EAGER or open-in-view.
Optimistic vs pessimistic locking?Optimistic uses @Version and fails on conflict (retry). Pessimistic uses database locks (for update).
How do you do a bulk insert efficiently?SEQUENCE ids, jdbc.batch_size, order_inserts, flush and clear per batch, or JDBC/StatelessSession.
Second level cache: when?Read-mostly reference data, with an appropriate concurrency strategy, after measuring. Bulk SQL bypasses it.
What does readOnly = true do?Hibernate uses manual flush mode and skips dirty checking. Also a hint to the driver and database.

Scenario questions

  • Your endpoint takes 6 seconds for 500 orders. What do you check? SQL count (N+1), missing indexes, entities instead of projections, open-in-view, lazy collections inside the JSON mapper.
  • save() runs a SELECT before every INSERT. Why? The id is assigned and there is no @Version, so isNew is false and merge() runs. Implement Persistable or add @Version.
  • A batch import of 1 million rows runs out of memory. Why? The persistence context keeps every entity. Flush and clear in chunks, use SEQUENCE and batching, or StatelessSession/JDBC.
  • Two users edit the same record and one change disappears. Fix? @Version optimistic locking with ETag/If-Match, or atomic SQL.
  • A @Transactional method does not roll back. Why? Checked exception, exception swallowed, self invocation, private method, or wrong transaction manager (multiple datasources).
  • Tests pass on H2 but fail in production. Why? Dialect and type differences, and the first level cache hiding queries. Use Testcontainers and flush/clear.

Common mistake: Memorizing definitions only. Interviewers ask about SQL you would see: draw the statements a piece of code produces, explain why, and how you would count and reduce them.

Interview questions

Which JPA topics are asked most?

Entity states and persistence context, lazy loading and N+1, transactions and rollback rules, locking, pagination and projections, and how Spring Data repositories work.

How do I practice?

Build an order/customer model, turn SQL logging on, and try each example: find with lazy access, fetch join, batch inserts, optimistic lock conflict. Watch the SQL.

What shows senior level knowledge?

Talking about SQL count, indexes, batch inserts, keyset paging, locking strategies, and trade-offs such as when to skip entities and use projections or SQL.

JPA Exceptions and Troubleshooting Guide

Exception messages in JPA look scary but each has a clear cause. This table explains the common ones, how to read the stack trace, and how to debug unexpected behavior.

Common exceptions

LazyInitializationException: could not initialize proxy - no SessionLazy field accessed after the session closedFetch in the service (fetch join, entity graph, projection), return DTOs. Not EAGER

Reading a Hibernate stack trace

org.springframework.dao.DataIntegrityViolationException: could not execute statement [ERROR: duplicate key value violates unique constraint "uk_users_email"
   Detail: Key (email)=(ram@example.com) already exists.]
Caused by: org.hibernate.exception.ConstraintViolationException: could not execute statement
Caused by: org.postgresql.util.PSQLException: ERROR: duplicate key value ...
Read from the BOTTOM: the last "Caused by" is the real database error (constraint name, column, value).
The top exception is the Spring translation. Your handler should map DataIntegrityViolationException to 409 and read the constraint name from the root cause.
@ExceptionHandler(DataIntegrityViolationException.class)
ProblemDetail integrity(DataIntegrityViolationException ex) {
    Throwable root = NestedExceptionUtils.getMostSpecificCause(ex);
    String message = root.getMessage() != null && root.getMessage().contains("uk_users_email") ? "Email already registered" : "Data conflicts with existing data";
    return ProblemDetail.forStatusAndDetail(HttpStatus.CONFLICT, message);       // never return the raw SQL message to clients
}

Common mistake: Catching PersistenceException or generic Exception in service code and hiding the root cause. Log the most specific cause and map known exceptions (constraint, optimistic lock) to proper HTTP statuses in one exception handler.

Interview questions

How do I find the real cause in a long stack trace?

Read the last 'Caused by'. It contains the database error with the constraint, column and value. Higher exceptions are wrappers.

Why do I get 'no transaction is in progress'?

A modifying operation ran without @Transactional. Put @Transactional on the service method that changes data.

Why is my change not saved though no error appears?

The entity is not managed (detached or created with new) or the transaction is read-only, so no flush wrote the change.

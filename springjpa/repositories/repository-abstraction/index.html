Spring Data Repository Abstraction: Interfaces and Methods

Spring Data gives you a hierarchy of repository interfaces. You choose how much API to expose, and Spring generates the implementation. This page explains each interface, every method of JpaRepository, the semantics of save and delete, and how to expose only what you want.

The interface hierarchy (Spring Data 3)

Repository<T, ID>                              marker interface, no methods (you declare your own)
   └─ CrudRepository<T, ID>                    save, saveAll, findById, existsById, findAll, findAllById, count, deleteById, delete, deleteAll ...
        └─ ListCrudRepository<T, ID>           same, but findAll / findAllById / saveAll return List (not Iterable)
   └─ PagingAndSortingRepository<T, ID>        findAll(Sort), findAll(Pageable)          (NOT a sub interface of CrudRepository since Spring Data 3)
        └─ ListPagingAndSortingRepository<T, ID>
JpaRepository<T, ID> extends ListCrudRepository, ListPagingAndSortingRepository, QueryByExampleExecutor
   adds: flush, saveAndFlush, saveAllAndFlush, deleteAllInBatch, deleteAllByIdInBatch, getReferenceById, findAll(Example) ...

saveAll(entities)save in a loopBatched if configured

save(): what really happens

// SimpleJpaRepository (simplified from the real source)
@Transactional
public <S extends T> S save(S entity) {
    if (entityInformation.isNew(entity)) {
        entityManager.persist(entity);      // the SAME object becomes managed
        return entity;
    } else {
        return entityManager.merge(entity); // returns a DIFFERENT managed copy. The passed object stays detached
    }
}
// isNew: entity has @Version (wrapper) ? version == null : id == null (primitive id: id == 0)    or Persistable#isNew()
// The classic bug
Product detached = new Product("X", BigDecimal.ONE, "c");
detached.setId(5L);                              // an existing row
Product saved = repository.save(detached);       // merge: copies state into a managed instance
detached.setName("changed");                     // NOT tracked: detached is not the managed object
saved.setName("tracked");                        // tracked. Written at commit

// Inside a transaction you often need no save() for changes at all:
@Transactional
public void rename(Long id, String name) {
    Product p = repository.findById(id).orElseThrow();   // managed
    p.setName(name);                                     // dirty checking writes the UPDATE at commit
}

delete: entity vs batch

repository.deleteById(5L);            // select product where id=5;  then  delete from product where id=5   (cascade and callbacks work)
repository.deleteAllInBatch();         // delete from product     (one statement, ignores cascades, JPA callbacks and the persistence context)
repository.deleteAllByIdInBatch(ids);  // delete from product where id in (...)

@NoRepositoryBean
public interface ReadOnlyRepository<T, ID> extends Repository<T, ID> {       // no save, no delete: cannot be misused
    Optional<T> findById(ID id);
    List<T> findAll();
}

public interface CountryRepository extends ReadOnlyRepository<Country, String> { }

Repository scanning and configuration

    queryLookupStrategy = QueryLookupStrategy.Key.CREATE_IF_NOT_FOUND,
    bootstrapMode = BootstrapMode.DEFERRED)                   // create repositories in the background at startup
class RepositoryConfig { }
  • Repository beans are singletons and thread safe. Transaction and EntityManager come from the current thread.
  • Repository methods are transactional by themselves: reads use readOnly, writes use a normal transaction. A service @Transactional joins them into one.
  • @Repository is not needed on the interface. Spring Data registers it and translates exceptions.

Common mistake: Calling repository.save(detached) and continuing to work with the original object. merge() returns a new managed copy and the original stays detached, so later changes are lost. Use the return value of save().

Interview questions

What is the difference between findById and getReferenceById?

findById runs a SELECT and returns Optional. getReferenceById returns a lazy proxy without SQL, useful to set a foreign key, and throws EntityNotFoundException when first used if the row does not exist.

Is calling save() required inside a @Transactional method?

Not for changes to managed entities: dirty checking writes them at commit. save() is needed for new entities (persist) or detached ones (merge).

What is the difference between deleteAll and deleteAllInBatch?

deleteAll loads each entity and deletes it one by one, running cascades and callbacks. deleteAllInBatch runs a single DELETE statement and skips cascades, callbacks and the persistence context.

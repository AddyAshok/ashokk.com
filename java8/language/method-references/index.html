Method References in Java 8

A method reference is a shorter form of a lambda that only calls one existing method. You write it with the :: operator. It makes code shorter and easier to read.

How it works in depth

A method reference is only another way to write a lambda. The compiler converts it, so anything you write as a method reference can also be written as a lambda. The rule is: (args) -> Class.method(args) becomes Class::method.

Know the difference between ClassName::instanceMethod and object::method. With String::length, the first parameter of the functional interface becomes the object on which the method is called. With object::method, the object is fixed and all parameters are passed as arguments to the method.

Key points

  • Static method: ClassName::staticMethod (Util::isLong).
  • Method of a specific object: object::method (System.out::println).
  • Method of any object of a type: ClassName::instanceMethod (String::length).
  • Constructor: ClassName::new (ArrayList::new). The method must match the functional interface signature.

Real life example

Instead of writing the whole instruction again, you just point to a method that already does the job.

Example 1: Basics

Save as Main.java, compile with javac Main.java and run with java Main (Java 8 or higher).

import java.util.*;
import java.util.function.*;

public class Main {
    public static void main(String[] args) {
        List<String> names = Arrays.asList("Ram", "Sita", "Laxman");
        names.forEach(System.out::println);
        Predicate<String> longName = Util::isLong;
        System.out.println(longName.test("Sita"));
        Function<String, Integer> len = String::length;
        System.out.println(len.apply("Java"));
        Supplier<List<String>> maker = ArrayList::new;
        List<String> fresh = maker.get();
        fresh.add("New");
        System.out.println(fresh);
    }
}

class Util {
    static boolean isLong(String s) { return s.length() > 3; }
}

Output:

Ram
Sita
Laxman
true
4
[New]

Example 2: All four types side by side

import java.util.function.*;

public class Main {
    public static void main(String[] args) {
        Function<String, Integer> parse = Integer::parseInt;            // static method
        Printer printer = new Printer();
        Consumer<String> c = printer::print;                            // method of a specific object
        Function<String, String> trim = String::trim;                   // method of any object of a type
        Function<String, Person> create = Person::new;                  // constructor
        System.out.println(parse.apply("42") + 1);
        c.accept("hello");
        System.out.println("[" + trim.apply("  spaces  ") + "]");
        System.out.println(create.apply("Ram"));
    }
}

class Printer {
    void print(String s) { System.out.println("Printer: " + s); }
}
class Person {
    String name;
    Person(String name) { this.name = name; }
    public String toString() { return "Person " + name; }
}

Output:

43
Printer: hello
[spaces]
Person Ram

Example 3: Method references with streams

import java.util.*;
import java.util.stream.*;

public class Main {
    public static void main(String[] args) {
        List<String> names = Arrays.asList("ram", "sita", "amit");
        List<String> upper = names.stream().map(String::toUpperCase).collect(Collectors.toList());
        System.out.println(upper);
        List<Integer> lengths = names.stream().map(String::length).collect(Collectors.toList());
        System.out.println(lengths);
        System.out.println(names.stream().sorted(String::compareTo).collect(Collectors.toList()));
        System.out.println(Stream.of("1", "2", "3").map(Integer::valueOf).reduce(0, Integer::sum));
    }
}

Output:

[RAM, SITA, AMIT]
[3, 4, 4]
[amit, ram, sita]
6

Common mistake: If a method is overloaded, the compiler may not know which one you mean. Use a lambda in that case.

Interview questions

Method reference or lambda, which is better?

Both give the same result. Use a method reference when the lambda only calls one method, because it is shorter and clearer. Use a lambda when you need extra logic.

Can I reference a constructor that takes arguments?

Yes, if the functional interface matches. For example Function<String, Person> can use Person::new for a constructor Person(String).

Does System.out::println work for any type?

Yes. println is overloaded, and the compiler picks the right version from the element type.

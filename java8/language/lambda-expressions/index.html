Lambda Expressions in Java 8

A lambda expression is a short way to write an anonymous function. It lets you pass code (behavior) as a value, so you write much less code than with anonymous inner classes. Syntax: (parameters) -> expression, or (parameters) -> { statements }.

How it works in depth

Behind the scenes a lambda is not an anonymous inner class. The compiler uses the invokedynamic instruction and the JVM creates the function object at run time. Because of this, lambdas are lighter than anonymous classes and do not create a separate .class file.

The type of a lambda comes from where you use it (target typing). The same text x -> x * 2 can be a Function<Integer,Integer> or an IntUnaryOperator, depending on the variable it is assigned to. The body can be a single expression (its value is returned automatically) or a block with braces and a return statement.

Key points

  • It can be used only where a functional interface is expected.
  • Parameter types are optional because Java infers them. With one parameter you can drop the brackets.
  • A lambda can use a local variable only if it is final or effectively final (never changed).
  • Inside a lambda, this means the enclosing class, not the lambda itself.

Real life example

Telling a friend "do this when you reach" instead of building a whole helper class for one small instruction.

Example 1: Basics

Save as Main.java, compile with javac Main.java and run with java Main (Java 8 or higher).

import java.util.*;
import java.util.function.*;

public class Main {
    public static void main(String[] args) {
        Runnable r = () -> System.out.println("Hello from lambda");
        r.run();
        Comparator<String> byLength = (a, b) -> a.length() - b.length();
        List<String> names = Arrays.asList("Charlie", "Al", "Bob");
        Collections.sort(names, byLength);
        System.out.println(names);
        BinaryOperator<Integer> add = (x, y) -> x + y;
        System.out.println(add.apply(3, 4));
    }
}

Output:

Hello from lambda
[Al, Bob, Charlie]
7

Example 2: Old way (anonymous class) vs lambda

import java.util.*;

public class Main {
    public static void main(String[] args) {
        List<String> names = Arrays.asList("Charlie", "Al", "Bob");
        Collections.sort(names, new Comparator<String>() {
            public int compare(String a, String b) { return a.length() - b.length(); }
        });
        System.out.println("Anonymous class: " + names);
        List<String> names2 = Arrays.asList("Charlie", "Al", "Bob");
        Collections.sort(names2, (a, b) -> a.length() - b.length());
        System.out.println("Lambda: " + names2);
    }
}

Output:

Anonymous class: [Al, Bob, Charlie]
Lambda: [Al, Bob, Charlie]

Example 3: Lambda syntax variations

import java.util.function.*;

public class Main {
    public static void main(String[] args) {
        Runnable noParam = () -> System.out.println("no parameter");
        Function<Integer, Integer> oneParam = x -> x * 2;
        BiFunction<Integer, Integer, Integer> twoParams = (x, y) -> x + y;
        BiFunction<Integer, Integer, Integer> typed = (Integer x, Integer y) -> x * y;
        Function<Integer, String> block = n -> {
            String size = n > 10 ? "big" : "small";
            return n + " is " + size;
        };
        noParam.run();
        System.out.println(oneParam.apply(5));
        System.out.println(twoParams.apply(2, 3));
        System.out.println(typed.apply(4, 5));
        System.out.println(block.apply(20));
    }
}

Output:

no parameter
10
5
20
20 is big

Example 4: Using local variables inside a lambda

import java.util.function.*;

public class Main {
    public static void main(String[] args) {
        int base = 100;
        Function<Integer, Integer> addBase = x -> x + base;
        System.out.println(addBase.apply(5));
        int[] counter = {0};
        Runnable inc = () -> counter[0]++;
        inc.run();
        inc.run();
        System.out.println(counter[0]);
    }
}

Output:

105
2

Common mistake: Changing a local variable inside a lambda gives a compile error. If you really need a counter, use an array or AtomicInteger.

Interview questions

Can a lambda be used without a functional interface?

No. The target type of a lambda must always be a functional interface.

Is a lambda the same as an anonymous class?

No. Inside a lambda, this means the enclosing class, but inside an anonymous class this means the anonymous object. They also compile differently (invokedynamic vs a separate class).

Why must captured local variables be effectively final?

A lambda may run later or on another thread. Local variables live on the stack, so Java copies their value. Allowing changes would create confusing and unsafe code.

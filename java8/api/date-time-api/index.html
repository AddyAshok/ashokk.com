Date and Time API in Java 8

Java 8 added the java.time package. The old Date and Calendar classes were mutable, not thread-safe and confusing (months started at 0). The new classes are immutable, thread-safe and clear.

Key points

  • LocalDate (date), LocalTime (time), LocalDateTime (both), ZonedDateTime (with time zone), Instant (machine time).
  • Period measures days, months and years. Duration measures hours, minutes and seconds.
  • DateTimeFormatter formats and parses text.
  • Every change like plusDays() returns a new object. The original stays the same.

Real life example

A calendar and a clock that never get scribbled on. Every change gives you a fresh copy.

Complete Java example

Save this as Main.java, then run javac Main.java and java Main (Java 8 or higher).

import java.time.*;
import java.time.format.*;

public class Main {
    public static void main(String[] args) {
        LocalDate date = LocalDate.of(2024, 3, 15);
        System.out.println(date);
        System.out.println(date.plusDays(20));
        System.out.println(date.getDayOfWeek());
        System.out.println(date.isLeapYear());
        LocalTime time = LocalTime.of(14, 30);
        LocalDateTime dt = LocalDateTime.of(date, time);
        System.out.println(dt.format(DateTimeFormatter.ofPattern("dd-MM-yyyy HH:mm")));
        Period p = Period.between(LocalDate.of(2000, 1, 1), date);
        System.out.println(p.getYears() + " years, " + p.getMonths() + " months");
        Duration d = Duration.between(LocalTime.of(9, 0), time);
        System.out.println(d.toMinutes() + " minutes");
        System.out.println(LocalDate.parse("2025-01-01").getMonth());
    }
}

Common mistake: Ignoring that objects are immutable. date.plusDays(5) alone does nothing; you must use the returned value.

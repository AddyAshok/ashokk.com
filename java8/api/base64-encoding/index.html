Base64 Encoding in Java 8

Java 8 added java.util.Base64 for encoding binary data as text and decoding it back. It is used in emails, URLs, tokens and JSON. Base64 is encoding, not encryption, so it gives no security.

How it works in depth

Base64 turns every 3 bytes into 4 printable characters (A-Z, a-z, 0-9, + and /), so the output is about 33 percent bigger. If the input length is not a multiple of 3, one or two = padding characters are added. The URL encoder uses - and _ instead of + and /, so the result is safe in URLs and file names.

Java 8 provides three encoder and decoder pairs: Basic, URL and MIME. Always pass a charset such as UTF-8 when converting between String and bytes. Decoding invalid input throws IllegalArgumentException.

Key points

  • Basic: getEncoder() and getDecoder().
  • URL and filename safe: getUrlEncoder() and getUrlDecoder().
  • MIME: getMimeEncoder() breaks long output into lines.
  • withoutPadding() removes the trailing = characters.

Real life example

Packing a fragile item in a standard box so it can travel through the post safely. Anyone can open the box.

Example 1: Basics

Save as Main.java, compile with javac Main.java and run with java Main (Java 8 or higher).

import java.util.*;
import java.nio.charset.StandardCharsets;

public class Main {
    public static void main(String[] args) {
        String original = "Java 8 is great!";
        String encoded = Base64.getEncoder().encodeToString(original.getBytes(StandardCharsets.UTF_8));
        System.out.println(encoded);
        String decoded = new String(Base64.getDecoder().decode(encoded), StandardCharsets.UTF_8);
        System.out.println(decoded);
        String url = Base64.getUrlEncoder().withoutPadding().encodeToString("a?b&c=d>".getBytes(StandardCharsets.UTF_8));
        System.out.println(url);
    }
}

Output:

SmF2YSA4IGlzIGdyZWF0IQ==
Java 8 is great!
YT9iJmM9ZD4

Example 2: Basic, URL and MIME encoders

import java.util.*;
import java.nio.charset.StandardCharsets;

public class Main {
    public static void main(String[] args) {
        byte[] data = "Hello, Java 8 >>> ???".getBytes(StandardCharsets.UTF_8);
        System.out.println(Base64.getEncoder().encodeToString(data));
        System.out.println(Base64.getUrlEncoder().encodeToString(data));
        System.out.println(Base64.getEncoder().withoutPadding().encodeToString("ab".getBytes(StandardCharsets.UTF_8)));
        System.out.println(Base64.getEncoder().encodeToString("ab".getBytes(StandardCharsets.UTF_8)));
        StringBuilder longText = new StringBuilder();
        for (int i = 0; i < 60; i++) longText.append("A");
        String mime = Base64.getMimeEncoder().encodeToString(longText.toString().getBytes(StandardCharsets.UTF_8));
        System.out.println(mime.split("\r\n").length + " lines");
    }
}

Output:

SGVsbG8sIEphdmEgOCA+Pj4gPz8/
SGVsbG8sIEphdmEgOCA-Pj4gPz8_
YWI
YWI=
2 lines

Example 3: Decoding and handling bad input

import java.util.*;
import java.nio.charset.StandardCharsets;

public class Main {
    public static void main(String[] args) {
        String token = "user:secret";
        String encoded = Base64.getEncoder().encodeToString(token.getBytes(StandardCharsets.UTF_8));
        System.out.println("Encoded: " + encoded);
        String[] parts = new String(Base64.getDecoder().decode(encoded), StandardCharsets.UTF_8).split(":");
        System.out.println(parts[0] + " / " + parts[1]);
        try {
            Base64.getDecoder().decode("not valid base64!!");
        } catch (IllegalArgumentException e) {
            System.out.println("Invalid Base64 input");
        }
        byte[] raw = {1, 2, 3, 4, 5};
        System.out.println(Base64.getEncoder().encodeToString(raw));
        System.out.println(Arrays.toString(Base64.getDecoder().decode("AQIDBAU=")));
    }
}

Output:

Encoded: dXNlcjpzZWNyZXQ=
user / secret
Invalid Base64 input
AQIDBAU=
[1, 2, 3, 4, 5]

Common mistake: Storing passwords with Base64 and thinking they are protected. Anyone can decode it in one line.

Interview questions

Is Base64 encryption?

No. It is only an encoding that anyone can reverse. It gives no security, so never use it to protect passwords or secrets.

Why does Base64 output end with = characters?

The = characters are padding. They fill the last group when the input length is not a multiple of 3 bytes.

What is the difference between the basic and URL encoder?

The URL encoder replaces + with - and / with _, so the text can be used safely in URLs and file names.

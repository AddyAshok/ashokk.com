New Methods in Map in Java 8

Java 8 added methods to Map that replace common if-else code: getOrDefault, putIfAbsent, computeIfAbsent, computeIfPresent, compute and merge.

How it works in depth

These methods turn check-then-act code into one line. For compute, computeIfPresent and merge, if the function returns null, the key is removed from the map. This makes them useful for updating and deleting in one step.

merge is the best tool for counting: map.merge(word, 1, Integer::sum). computeIfAbsent is the best tool for a Map of Lists (grouping). In ConcurrentHashMap these methods are atomic, so they are safe for many threads.

Key points

  • getOrDefault(key, default): returns default when the key is missing.
  • putIfAbsent(key, value): puts only if the key has no value.
  • computeIfAbsent(key, fn): creates the value if missing. Perfect for Map of Lists.
  • merge(key, value, fn): adds the value or combines with the old one. Perfect for counting.

Real life example

A register book: if the name is not there, write it; if it is there, update its count.

Example 1: Basics

Save as Main.java, compile with javac Main.java and run with java Main (Java 8 or higher).

import java.util.*;

public class Main {
    public static void main(String[] args) {
        Map<String, Integer> stock = new HashMap<>();
        stock.put("apple", 10);
        System.out.println(stock.getOrDefault("mango", 0));
        stock.putIfAbsent("apple", 99);
        stock.putIfAbsent("banana", 5);
        stock.merge("apple", 5, Integer::sum);
        stock.computeIfPresent("banana", (k, v) -> v * 2);
        Map<String, List<String>> groups = new HashMap<>();
        groups.computeIfAbsent("fruits", k -> new ArrayList<>()).add("mango");
        groups.computeIfAbsent("fruits", k -> new ArrayList<>()).add("kiwi");
        System.out.println(new TreeMap<>(stock));
        System.out.println(groups);
    }
}

Output:

0
{apple=15, banana=10}
{fruits=[mango, kiwi]}

Example 2: Word count with merge

import java.util.*;

public class Main {
    public static void main(String[] args) {
        String text = "to be or not to be";
        Map<String, Integer> count = new TreeMap<>();
        for (String w : text.split(" ")) {
            count.merge(w, 1, Integer::sum);
        }
        System.out.println(count);
        Map<String, Integer> old = new TreeMap<>();
        for (String w : text.split(" ")) {
            if (old.containsKey(w)) old.put(w, old.get(w) + 1); else old.put(w, 1);
        }
        System.out.println(old.equals(count));
    }
}

Output:

{be=2, not=1, or=1, to=2}
true

Example 3: compute, computeIfPresent and removing with null

import java.util.*;

public class Main {
    public static void main(String[] args) {
        Map<String, Integer> m = new TreeMap<>();
        m.put("a", 1);
        m.put("b", 2);
        m.compute("a", (k, v) -> v == null ? 1 : v + 10);
        m.compute("z", (k, v) -> v == null ? 1 : v + 10);
        m.computeIfPresent("b", (k, v) -> null);
        System.out.println(m);
        System.out.println(m.getOrDefault("b", -1));
        m.replace("a", 100);
        m.remove("z", 5);
        System.out.println(m);
        m.remove("z", 1);
        System.out.println(m);
    }
}

Output:

{a=11, z=1}
-1
{a=100, z=1}
{a=100}

Common mistake: Using computeIfAbsent and changing the same map inside the function. That can throw ConcurrentModificationException.

Interview questions

What is the difference between putIfAbsent and computeIfAbsent?

putIfAbsent takes a ready value, which is always created. computeIfAbsent takes a function that runs only when the key is missing, so it is better when the value is costly to create.

What happens if the function of merge returns null?

The key is removed from the map.

Are these methods thread-safe?

Only in ConcurrentHashMap, where they are atomic. In a normal HashMap they are not thread-safe.

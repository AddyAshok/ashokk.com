Optional in Java 8

Optional<T> is a container that may or may not hold a non-null value. It makes the "no value" case visible in the code, so you avoid NullPointerException.

How it works in depth

Optional is a value-based, immutable class meant to be a return type that says the result may be missing. Note that orElse always evaluates its argument, while orElseGet runs the supplier only when the Optional is empty. This matters when creating the default value is expensive.

Optional works well with streams: map, flatMap and filter let you chain safe transformations without null checks. Methods like ifPresentOrElse(), or() and stream() were added in Java 9 and are not available in Java 8.

Key points

  • Create: Optional.of(x) (throws NPE if x is null), Optional.ofNullable(x), Optional.empty().
  • Read: orElse(default), orElseGet(supplier), orElseThrow(supplier), ifPresent(consumer), isPresent().
  • Transform: map(), flatMap(), filter().
  • Use it as a return type. Do not use it for fields or method parameters.

Real life example

A gift box that may be empty. You check inside before using it.

Example 1: Basics

Save as Main.java, compile with javac Main.java and run with java Main (Java 8 or higher).

import java.util.*;

public class Main {
    public static void main(String[] args) {
        Optional<String> name = Optional.of("Ram");
        Optional<String> empty = Optional.empty();
        Optional<String> maybe = Optional.ofNullable(null);
        System.out.println(name.isPresent());
        System.out.println(empty.orElse("Unknown"));
        System.out.println(maybe.orElseGet(() -> "Generated"));
        name.ifPresent(n -> System.out.println("Hello " + n));
        System.out.println(name.map(String::toUpperCase).get());
        System.out.println(name.filter(n -> n.startsWith("S")).isPresent());
        try { empty.orElseThrow(() -> new IllegalStateException("No value")); }
        catch (IllegalStateException e) { System.out.println("Error: " + e.getMessage()); }
    }
}

Output:

true
Unknown
Generated
Hello Ram
RAM
false
Error: No value

Example 2: Old null checks vs Optional chaining

import java.util.*;

public class Main {
    public static void main(String[] args) {
        User u1 = new User(new Address("Delhi"));
        User u2 = new User(null);
        System.out.println(u1.getAddress().map(Address::getCity).orElse("Unknown city"));
        System.out.println(u2.getAddress().map(Address::getCity).orElse("Unknown city"));
        System.out.println(Optional.of(u1).flatMap(User::getAddress).isPresent());
    }
}

class Address { String city; Address(String c) { city = c; } String getCity() { return city; } }
class User {
    Address address;
    User(Address a) { address = a; }
    Optional<Address> getAddress() { return Optional.ofNullable(address); }
}

Output:

Delhi
Unknown city
true

Example 3: orElse vs orElseGet

import java.util.*;
import java.util.function.*;

public class Main {
    public static void main(String[] args) {
        Supplier<String> expensive = () -> { System.out.println("  computing default..."); return "default"; };
        Optional<String> present = Optional.of("value");
        System.out.println("orElse:");
        System.out.println(present.orElse(expensive.get()));
        System.out.println("orElseGet:");
        System.out.println(present.orElseGet(expensive));
        Optional<String> emptyOpt = Optional.empty();
        System.out.println(emptyOpt.orElseGet(expensive));
    }
}

Output:

orElse:
  computing default...
value
orElseGet:
value
  computing default...
default

Common mistake: Calling get() without checking. That throws NoSuchElementException, just like a null problem. Prefer orElse or ifPresent.

Interview questions

Should Optional be used as a field or method parameter?

No. It was designed for return types. As a field it is not serializable and adds memory cost, and as a parameter it makes calling code awkward.

What is the difference between Optional.of and Optional.ofNullable?

of() throws NullPointerException if the value is null. ofNullable() returns an empty Optional for null.

Why is calling get() directly a bad practice?

get() throws NoSuchElementException on an empty Optional, which is the same problem as a null pointer. Use orElse, orElseGet, ifPresent or map instead.

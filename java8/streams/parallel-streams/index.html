Parallel Streams in Java 8

A parallel stream splits the work across many threads (the ForkJoin common pool) so it can use all CPU cores. Use stream.parallel() or collection.parallelStream().

Key points

  • Best for large data and CPU-heavy, independent tasks.
  • Not good for small data, I/O work, or tasks that change shared variables (not thread-safe).
  • forEach may print in any order. Use forEachOrdered to keep the order.
  • Always measure. Parallel is not always faster because splitting and merging cost time.

Real life example

Ten people counting a big pile of coins together instead of one person counting alone.

Complete Java example

Save this as Main.java, then run javac Main.java and java Main (Java 8 or higher).

import java.util.*;
import java.util.stream.*;

public class Main {
    public static void main(String[] args) {
        long sum = IntStream.rangeClosed(1, 1000000).parallel().asLongStream().sum();
        System.out.println(sum);
        List<Integer> nums = Arrays.asList(1, 2, 3, 4, 5, 6);
        System.out.println(nums.parallelStream().map(n -> n * n).collect(Collectors.toList()));
        nums.parallelStream().forEachOrdered(n -> System.out.print(n + " "));
        System.out.println();
        System.out.println(nums.parallelStream().isParallel());
    }
}

Output

500000500000
[1, 4, 9, 16, 25, 36]
1 2 3 4 5 6 
true

Common mistake: Modifying a shared list or counter inside a parallel stream gives wrong results. Use collect() or reduce() instead.

Behavioral Design Patterns in Java

Behavioral patterns are about how objects talk to each other and share work. They make communication clear and loosely connected. There are 11 behavioral patterns.

1. Chain of Responsibility

A request moves along a chain of handlers. Each handler either handles it or passes it to the next one.

Real life: A leave request goes to the manager first. If the manager cannot approve, it goes to the director.

Use when: More than one object can handle a request and you do not know which one in advance.

abstract class Handler {
    private Handler next;
    Handler setNext(Handler n) { next = n; return n; }
    void handle(int amount) {
        if (next != null) next.handle(amount);      // pass forward
        else System.out.println("Rejected");
    }
}
class Manager extends Handler {
    void handle(int a) { if (a <= 1000) System.out.println("Manager approved"); else super.handle(a); }
}
class Director extends Handler {
    void handle(int a) { if (a <= 10000) System.out.println("Director approved"); else super.handle(a); }
}

Handler m = new Manager();
m.setNext(new Director());
m.handle(500);      // Manager approved
m.handle(5000);     // Director approved
m.handle(50000);    // Rejected

2. Command

Command turns a request into an object. Because it is an object, you can store it, pass it around, delay it or undo it.

Real life: In a restaurant, the waiter writes your order on paper. The paper (command) goes to the chef.

Use when: You need buttons, menus, queues, or undo and redo.

interface Command { void execute(); }

class Light {
    void on()  { System.out.println("Light ON"); }
    void off() { System.out.println("Light OFF"); }
}
class LightOn  implements Command {
    private Light light;
    LightOn(Light l) { light = l; }
    public void execute() { light.on(); }
}
class LightOff implements Command {
    private Light light;
    LightOff(Light l) { light = l; }
    public void execute() { light.off(); }
}

class RemoteControl {                              // does not know what the command does
    private Command command;
    void setCommand(Command c) { command = c; }
    void press() { command.execute(); }
}

Light light = new Light();
RemoteControl remote = new RemoteControl();
remote.setCommand(new LightOn(light));
remote.press();                                    // Light ON

3. Interpreter

Interpreter defines a small language (grammar) and a way to read and calculate sentences of that language.

Real life: A calculator understands 10 + 5 - 3 and gives the answer.

Use when: You have simple rules or expressions that repeat, like math formulas, search filters or rules.

interface Expr { int eval(); }

class Num implements Expr {
    private int n;
    Num(int n) { this.n = n; }
    public int eval() { return n; }
}
class Add implements Expr {
    private Expr left, right;
    Add(Expr l, Expr r) { left = l; right = r; }
    public int eval() { return left.eval() + right.eval(); }
}
class Sub implements Expr {
    private Expr left, right;
    Sub(Expr l, Expr r) { left = l; right = r; }
    public int eval() { return left.eval() - right.eval(); }
}

Expr e = new Sub(new Add(new Num(10), new Num(5)), new Num(3));   // (10 + 5) - 3
System.out.println(e.eval());                                     // 12

4. Iterator

Iterator gives a standard way to go through the items of a collection one by one, without showing how the collection is built inside.

Real life: Turning the pages of a book. You do not care how the book is bound.

Use when: You want to loop over a collection using a simple for-each loop.

class NameList implements Iterable<String> {
    private String[] names = {"Ram", "Sita", "Amit"};

    public Iterator<String> iterator() {
        return new Iterator<String>() {
            private int i = 0;
            public boolean hasNext() { return i < names.length; }
            public String next()     { return names[i++]; }
        };
    }
}

for (String name : new NameList()) {
    System.out.println(name);                      // Ram, Sita, Amit
}

5. Mediator

Mediator is a middle object. Objects talk to the mediator, not directly to each other. This removes tangled connections.

Real life: An air traffic controller. Planes talk to the tower, not to each other.

Use when: Many objects talk to many other objects and the code is becoming messy.

class ChatRoom {                                   // the mediator
    private List<User> users = new ArrayList<>();
    void join(User u) { users.add(u); }
    void send(String msg, User from) {
        for (User u : users)
            if (u != from) u.receive(msg, from.name);
    }
}

class User {
    String name;
    private ChatRoom room;
    User(String name, ChatRoom room) { this.name = name; this.room = room; room.join(this); }
    void send(String msg) { room.send(msg, this); }
    void receive(String msg, String from) { System.out.println(name + " got '" + msg + "' from " + from); }
}

ChatRoom room = new ChatRoom();
User ram = new User("Ram", room);
User sita = new User("Sita", room);
ram.send("Hi");                                    // Sita got 'Hi' from Ram

6. Memento

Memento saves a snapshot of an object's state so you can go back to it later. It does this without breaking encapsulation.

Real life: Save point in a video game, or Ctrl+Z in a text editor.

Use when: You need undo, rollback or restore features.

class Editor {
    private String text = "";
    void type(String t) { text += t; }
    String getText()    { return text; }

    Snapshot save()          { return new Snapshot(text); }   // create memento
    void restore(Snapshot s) { text = s.text; }               // go back

    static class Snapshot {
        private final String text;
        private Snapshot(String text) { this.text = text; }
    }
}

Editor e = new Editor();
e.type("Hello");
Editor.Snapshot saved = e.save();
e.type(" World");
e.restore(saved);
System.out.println(e.getText());                   // Hello

7. Observer

When one object changes, all objects that subscribed to it are told automatically.

Real life: YouTube: when a channel uploads a video, all subscribers get a notification.

Use when: One change must update many other objects, and you do not want them tightly connected.

interface Observer { void update(String news); }

class NewsChannel {                                // the subject
    private List<Observer> subscribers = new ArrayList<>();
    void subscribe(Observer o) { subscribers.add(o); }
    void publish(String news) {
        for (Observer o : subscribers) o.update(news);   // tell everyone
    }
}

class Reader implements Observer {
    private String name;
    Reader(String name) { this.name = name; }
    public void update(String news) { System.out.println(name + " read: " + news); }
}

NewsChannel channel = new NewsChannel();
channel.subscribe(new Reader("Ram"));
channel.subscribe(new Reader("Sita"));
channel.publish("Breaking news!");                 // Ram and Sita both get it

8. State

State lets an object change its behavior when its internal state changes. Each state is its own class.

Real life: A traffic light: red, green and yellow behave differently and follow each other in order.

Use when: An object has many states and big if-else or switch blocks are making the code hard to read.

interface State {
    void next(TrafficLight light);
    String color();
}
class Red    implements State { public void next(TrafficLight l) { l.state = new Green();  } public String color() { return "RED"; } }
class Green  implements State { public void next(TrafficLight l) { l.state = new Yellow(); } public String color() { return "GREEN"; } }
class Yellow implements State { public void next(TrafficLight l) { l.state = new Red();    } public String color() { return "YELLOW"; } }

class TrafficLight {
    State state = new Red();
    void change() { state.next(this); }
}

TrafficLight light = new TrafficLight();
System.out.println(light.state.color());           // RED
light.change();
System.out.println(light.state.color());           // GREEN

9. Strategy

Strategy keeps several ways (algorithms) to do one job in separate classes. You can switch between them while the program runs.

Real life: Going to the office by car, bus or bike. The goal is same, the way is different.

Use when: You have many ways to do the same task, like payment methods, sorting or discounts.

interface Payment { void pay(int amount); }

class UpiPayment  implements Payment { public void pay(int a) { System.out.println("Paid " + a + " by UPI"); } }
class CardPayment implements Payment { public void pay(int a) { System.out.println("Paid " + a + " by Card"); } }

class Cart {
    private Payment payment;
    void setPayment(Payment p) { payment = p; }           // choose the strategy
    void checkout(int amount)  { payment.pay(amount); }
}

Cart cart = new Cart();
cart.setPayment(new UpiPayment());
cart.checkout(500);                                       // Paid 500 by UPI
cart.setPayment(new CardPayment());
cart.checkout(800);                                       // Paid 800 by Card

10. Template Method

A parent class fixes the steps of an algorithm. Child classes fill in only the steps that are different.

Real life: Making a hot drink: boil water, brew, pour. Only the brewing is different for tea and coffee.

Use when: Several classes follow the same steps but a few steps are different.

abstract class Beverage {
    final void prepare() {                         // the template: fixed order
        boilWater();
        brew();
        pour();
    }
    void boilWater() { System.out.println("Boil water"); }
    void pour()      { System.out.println("Pour in cup"); }
    abstract void brew();                          // children must write this step
}

class Tea    extends Beverage { void brew() { System.out.println("Steep tea leaves"); } }
class Coffee extends Beverage { void brew() { System.out.println("Drip coffee"); } }

new Tea().prepare();      // Boil water, Steep tea leaves, Pour in cup
new Coffee().prepare();   // Boil water, Drip coffee, Pour in cup

11. Visitor

Visitor lets you add a new operation to many classes without changing those classes. The operation lives in a separate visitor class.

Real life: A tax officer visits different businesses (shop, factory) and calculates tax in a different way for each.

Use when: You have a stable set of classes but you keep adding new operations on them.

interface Shape { void accept(Visitor v); }
class Circle implements Shape { double r = 2; public void accept(Visitor v) { v.visit(this); } }
class Square implements Shape { double s = 3; public void accept(Visitor v) { v.visit(this); } }

interface Visitor {
    void visit(Circle c);
    void visit(Square s);
}

class AreaVisitor implements Visitor {             // new operation, shapes are untouched
    public void visit(Circle c) { System.out.println("Circle area: " + Math.PI * c.r * c.r); }
    public void visit(Square s) { System.out.println("Square area: " + s.s * s.s); }
}

Shape[] shapes = { new Circle(), new Square() };
for (Shape sh : shapes) sh.accept(new AreaVisitor());

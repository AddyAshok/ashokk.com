Creational Design Patterns in Java

Creational patterns are about creating objects. They hide how objects are made, so your code stays flexible and easy to change. There are 5 creational patterns.

1. Singleton

Singleton makes sure a class has only one object. Everyone in the program uses that same object.

Real life: A country has only one president. Everybody talks to the same person.

Use when: You need exactly one shared object, such as a logger, app settings or a database connection.

class Logger {
    private static Logger instance;        // the only object
    private Logger() {}                    // nobody can write new Logger()

    public static Logger getInstance() {
        if (instance == null) {
            instance = new Logger();       // created only the first time
        }
        return instance;
    }
    void log(String msg) { System.out.println("LOG: " + msg); }
}

Logger a = Logger.getInstance();
Logger b = Logger.getInstance();
System.out.println(a == b);                // true, same object
// Tip: for multi-threading, use an enum: enum Logger { INSTANCE }

2. Factory Method

A parent class has a method that creates an object. Each child class decides which object to create. The main code never says new Truck() or new Ship().

Real life: A logistics company delivers by road or by sea. Each branch picks its own vehicle.

Use when: You do not know in advance which exact class you will need, and you want subclasses to decide.

interface Transport { void deliver(); }
class Truck implements Transport { public void deliver() { System.out.println("Deliver by road"); } }
class Ship  implements Transport { public void deliver() { System.out.println("Deliver by sea"); } }

abstract class Logistics {
    abstract Transport createTransport();          // the factory method
    void planDelivery() { createTransport().deliver(); }
}
class RoadLogistics extends Logistics { Transport createTransport() { return new Truck(); } }
class SeaLogistics  extends Logistics { Transport createTransport() { return new Ship(); } }

new SeaLogistics().planDelivery();                 // Deliver by sea

3. Abstract Factory

A factory that creates a whole family of related objects. All objects from one factory match each other.

Real life: A furniture shop sells a Modern set or a Classic set. A sofa and a chair from the same set always match.

Use when: You must create groups of objects that belong together, like dark theme and light theme widgets.

interface Button   { void draw(); }
interface Checkbox { void draw(); }

class DarkButton   implements Button   { public void draw() { System.out.println("Dark button"); } }
class DarkCheckbox implements Checkbox { public void draw() { System.out.println("Dark checkbox"); } }
class LightButton   implements Button   { public void draw() { System.out.println("Light button"); } }
class LightCheckbox implements Checkbox { public void draw() { System.out.println("Light checkbox"); } }

interface UIFactory { Button createButton(); Checkbox createCheckbox(); }
class DarkFactory  implements UIFactory {
    public Button createButton()     { return new DarkButton(); }
    public Checkbox createCheckbox() { return new DarkCheckbox(); }
}
class LightFactory implements UIFactory {
    public Button createButton()     { return new LightButton(); }
    public Checkbox createCheckbox() { return new LightCheckbox(); }
}

UIFactory f = new DarkFactory();     // change this one line to switch the whole theme
f.createButton().draw();             // Dark button
f.createCheckbox().draw();           // Dark checkbox

4. Builder

Builder creates a big object step by step. You set only the parts you want, then call build().

Real life: Ordering a pizza: you choose size, cheese and toppings one by one.

Use when: A class has many optional fields and a constructor with many parameters would be confusing.

class Pizza {
    private String size, cheese;
    private boolean olives;
    private Pizza(Builder b) { size = b.size; cheese = b.cheese; olives = b.olives; }

    static class Builder {
        private String size = "medium", cheese = "mozzarella";   // default values
        private boolean olives;
        Builder size(String s)    { size = s;   return this; }
        Builder cheese(String c)  { cheese = c; return this; }
        Builder olives(boolean o) { olives = o; return this; }
        Pizza build() { return new Pizza(this); }
    }
}

Pizza p = new Pizza.Builder().size("large").olives(true).build();

5. Prototype

Instead of creating a new object from zero, you copy (clone) an existing object.

Real life: Photocopying a filled form instead of writing it again.

Use when: Creating an object is slow or costly, and a copy of an existing object is faster.

class Sheep implements Cloneable {
    String name;
    Sheep(String name) { this.name = name; }

    public Sheep clone() {
        try { return (Sheep) super.clone(); }        // copies the object
        catch (CloneNotSupportedException e) { throw new AssertionError(); }
    }
}

Sheep dolly = new Sheep("Dolly");
Sheep copy = dolly.clone();
copy.name = "Dolly 2";                               // original is not changed
// Note: super.clone() is a shallow copy. Copy inner objects yourself if needed.

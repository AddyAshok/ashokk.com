Structural Design Patterns in Java

Structural patterns are about how classes and objects are joined together to make bigger structures. They keep the structure flexible and simple. There are 7 structural patterns.

1. Adapter

Adapter sits between two classes that do not fit together and translates one interface into the other.

Real life: A phone charger adapter lets a 3-pin plug work in a 2-pin socket.

Use when: You want to use an old or third-party class, but its methods do not match what your code expects.

class OldPrinter { void printText(String t) { System.out.println(t); } }   // cannot change this

interface Printer { void print(String t); }                                 // what our app expects

class PrinterAdapter implements Printer {
    private OldPrinter old = new OldPrinter();
    public void print(String t) { old.printText(t); }                        // translate the call
}

Printer p = new PrinterAdapter();
p.print("Hello");

2. Bridge

Bridge splits a class into two parts, what it is and how it works, so both can change on their own.

Real life: A remote control (abstraction) works with any device: TV, radio, etc. (implementation).

Use when: You have two things that can vary, like 3 remotes x 4 devices, and you do not want 12 classes.

interface Device { void on(); }
class Tv    implements Device { public void on() { System.out.println("TV on"); } }
class Radio implements Device { public void on() { System.out.println("Radio on"); } }

abstract class Remote {
    protected Device device;                       // this is the "bridge"
    Remote(Device d) { device = d; }
    abstract void press();
}
class BasicRemote extends Remote {
    BasicRemote(Device d) { super(d); }
    void press() { device.on(); }
}

new BasicRemote(new Tv()).press();                 // TV on
new BasicRemote(new Radio()).press();              // Radio on

3. Composite

Composite lets you treat one object and a group of objects in the same way. Objects are arranged like a tree.

Real life: A folder can hold files and other folders. You can ask any of them for its size.

Use when: Your data is a tree (parts inside parts) and you want one simple way to work with all of it.

interface Item { int size(); }

class File implements Item {
    private int size;
    File(int size) { this.size = size; }
    public int size() { return size; }
}

class Folder implements Item {
    private List<Item> items = new ArrayList<>();
    void add(Item i) { items.add(i); }
    public int size() {
        int total = 0;
        for (Item i : items) total += i.size();    // works for files and folders
        return total;
    }
}

Folder root = new Folder();
root.add(new File(10));
Folder sub = new Folder();
sub.add(new File(5));
root.add(sub);
System.out.println(root.size());                   // 15

4. Decorator

Decorator adds new features to an object by wrapping it, without changing its class.

Real life: Adding milk and sugar to a coffee. Each extra changes the price, but it is still a coffee.

Use when: You want to add features at run time and do not want a subclass for every combination.

interface Coffee { double cost(); }

class SimpleCoffee implements Coffee { public double cost() { return 50; } }

class Milk implements Coffee {
    private Coffee coffee;
    Milk(Coffee c) { coffee = c; }
    public double cost() { return coffee.cost() + 10; }     // wrap and add
}
class Sugar implements Coffee {
    private Coffee coffee;
    Sugar(Coffee c) { coffee = c; }
    public double cost() { return coffee.cost() + 5; }
}

Coffee c = new Sugar(new Milk(new SimpleCoffee()));
System.out.println(c.cost());                               // 65.0

5. Facade

Facade gives one simple class in front of a complex system. You call one method and it does many steps inside.

Real life: Pressing the power button on a computer. Many parts start, but you press only one button.

Use when: A system has many classes and you want an easy way to use it.

class Cpu    { void start() { System.out.println("CPU started"); } }
class Memory { void load()  { System.out.println("Memory loaded"); } }
class Disk   { void read()  { System.out.println("Disk read"); } }

class Computer {                                   // the facade
    private Cpu cpu = new Cpu();
    private Memory memory = new Memory();
    private Disk disk = new Disk();

    void turnOn() {                                // one easy method
        cpu.start();
        memory.load();
        disk.read();
    }
}

new Computer().turnOn();

6. Flyweight

Flyweight saves memory by sharing objects that are the same, instead of creating thousands of copies.

Real life: A game forest with 10,000 trees. All oak trees share one picture and only the position is different.

Use when: Your program needs a huge number of similar objects and memory is a problem.

class TreeType {                                   // shared data
    private String name;
    TreeType(String name) { this.name = name; }
    void draw(int x, int y) { System.out.println(name + " at " + x + "," + y); }
}

class TreeFactory {
    private static Map<String, TreeType> cache = new HashMap<>();
    static TreeType get(String name) {
        return cache.computeIfAbsent(name, TreeType::new);   // reuse if it exists
    }
}

TreeFactory.get("Oak").draw(1, 2);
TreeFactory.get("Oak").draw(5, 9);                 // same Oak object, only position changes

7. Proxy

Proxy is a stand-in object that controls access to the real object. It can delay creation, check permission or add logging.

Real life: A cheque is a proxy for cash in your bank account.

Use when: The real object is heavy or secret, and you want to load it only when it is really needed (lazy loading).

interface Image { void show(); }

class RealImage implements Image {
    RealImage(String file) { System.out.println("Loading " + file); }   // slow work
    public void show() { System.out.println("Showing image"); }
}

class ProxyImage implements Image {
    private String file;
    private RealImage real;
    ProxyImage(String file) { this.file = file; }
    public void show() {
        if (real == null) real = new RealImage(file);   // load only on first use
        real.show();
    }
}

Image img = new ProxyImage("photo.jpg");            // nothing loaded yet
img.show();                                         // now it loads and shows

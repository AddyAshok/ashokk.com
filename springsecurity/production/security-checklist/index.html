Spring Security Production Checklist

Use this checklist before every release. It is based on OWASP guidance and the mistakes seen most often in Spring applications.

Authentication

  • Passwords hashed with bcrypt, Argon2, scrypt or PBKDF2 through DelegatingPasswordEncoder. Cost set for about 100 to 300 ms.
  • Minimum 12 characters, breached password check, no composition rules that force weak patterns.
  • Login rate limit, lockout with expiry, and generic error messages.
  • MFA for admins and sensitive accounts.
  • Password reset by single-use, short-lived, hashed tokens. Email verification on registration.
  • No default or generated password in any real environment.

Sessions and tokens

  • Session cookie: HttpOnly, Secure, SameSite. Timeout set. New id after login.
  • JWT: asymmetric signing (RS256, ES256 or EdDSA), pinned algorithm, short expiry, iss and aud validated.
  • Refresh tokens: opaque, hashed in the database, rotated, reuse detection, revocation on logout and password change.
  • Keys and secrets from a vault or environment, never in Git. A rotation plan (kid and JWKS).

Authorization

  • Default deny: anyRequest().denyAll() or authenticated().
  • Ownership checks for every object (no IDOR).
  • Fine-grained checks with method security. Roles map to permissions.
  • Admin endpoints on a separate path and chain, with stronger rules and audit logging.
  • Tests for 401 and 403 on every endpoint.

Web protections

  • CSRF on for cookie based apps. Disabled only for stateless token APIs.
  • CORS: exact origins, no wildcard with credentials.
  • Security headers: CSP, HSTS, X-Frame-Options or frame-ancestors, nosniff, Referrer-Policy, Permissions-Policy.
  • HTTPS everywhere, HSTS, modern TLS. Redirect HTTP to HTTPS at the edge.
  • Request size limits, upload validation, and timeouts.

Data and code

  • Only parameterized queries. DTOs for input (no mass assignment).
  • Validation on every request DTO.
  • Errors: no stack traces or internal messages to clients. One generic error format.
  • Logs: no passwords, tokens, or card data. Audit log for logins, denials and admin actions.
  • Sensitive data encrypted at rest. Personal data minimized.

Operations

  • Actuator: only health (and info) public. Others behind authentication and on a private port.
  • Swagger UI, H2 console, debug endpoints disabled in production.
  • Dependencies scanned (Dependabot, OWASP Dependency-Check, Snyk) and updated regularly. Follow Spring security advisories.
  • Container image without root user, minimal base image.
  • Alerts on spikes of 401, 403, 429 and login failures.
  • Incident plan: how to revoke all sessions and tokens and rotate keys quickly.

Production baseline configuration

server.error.include-stacktrace=never
server.error.include-message=never
server.servlet.session.cookie.http-only=true
server.servlet.session.cookie.secure=true
server.servlet.session.cookie.same-site=lax
server.servlet.session.timeout=30m
server.forward-headers-strategy=framework
management.endpoints.web.exposure.include=health,info
management.endpoint.health.show-details=never
springdoc.swagger-ui.enabled=false
spring.h2.console.enabled=false
logging.level.org.springframework.security=WARN
@Bean
SecurityFilterChain secureBaseline(HttpSecurity http) throws Exception {
    http
        .authorizeHttpRequests(a -> a
            .requestMatchers("/actuator/health").permitAll()
            .requestMatchers("/admin/**").hasRole("ADMIN")
            .anyRequest().authenticated())                       // or denyAll for strict APIs
        .headers(h -> h
            .contentSecurityPolicy(c -> c.policyDirectives("default-src 'self'; frame-ancestors 'none'"))
            .httpStrictTransportSecurity(s -> s.includeSubDomains(true).maxAgeInSeconds(31536000)))
        .sessionManagement(s -> s.maximumSessions(3))
        .formLogin(Customizer.withDefaults())
        .logout(Customizer.withDefaults());
    return http.build();
}

Common mistake: Treating the checklist as a one-time task. Security changes with every feature. Add the checks to the pull request template, CI (dependency scan, security tests) and regular reviews.

Interview questions

What is the single most valuable security test?

An automated test that every endpoint returns 401 for anonymous users and 403 for the wrong role, plus ownership tests. It catches accidentally open endpoints.

How often should dependencies be updated?

Continuously. Enable Dependabot or Renovate, and apply Spring security patch releases quickly, because known CVEs are exploited within days.

Where do secrets belong?

In a secret manager (Vault, cloud secrets, Kubernetes Secrets with encryption) or environment variables set by the platform, never in the repository or the image.

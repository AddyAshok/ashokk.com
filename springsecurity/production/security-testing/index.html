Testing Spring Security

Security rules that are not tested break silently. Spring Security Test lets you simulate users, roles, JWTs and CSRF tokens, so 401 and 403 behavior is verified in every build.

Setup

<dependency>
    <groupId>org.springframework.security</groupId>
    <artifactId>spring-security-test</artifactId>
    <scope>test</scope>
</dependency>

Test 401 and 403 with MockMvc

@SpringBootTest
@AutoConfigureMockMvc
class OrderSecurityTest {

    @Autowired MockMvc mvc;

    @Test
    void anonymousGets401() throws Exception {
        mvc.perform(get("/api/orders")).andExpect(status().isUnauthorized());
    }

    @Test
    @WithMockUser(username = "ram", roles = "USER")
    void userCanReadButNotDelete() throws Exception {
        mvc.perform(get("/api/orders")).andExpect(status().isOk());
        mvc.perform(delete("/api/orders/1").with(csrf())).andExpect(status().isForbidden());
    }

    @Test
    @WithMockUser(roles = "ADMIN")
    void adminCanDelete() throws Exception {
        mvc.perform(delete("/api/orders/1").with(csrf())).andExpect(status().isNoContent());
    }

    @Test
    void postWithoutCsrfIsForbidden() throws Exception {
        mvc.perform(post("/api/orders").with(user("ram").roles("USER")).contentType("application/json").content("{}"))
           .andExpect(status().isForbidden());
    }
}

Test JWT protected APIs

@Test
void jwtWithScopeCanRead() throws Exception {
    mvc.perform(get("/api/orders")
            .with(jwt().jwt(j -> j.subject("ram").claim("roles", List.of("USER")))
                       .authorities(new SimpleGrantedAuthority("SCOPE_read"))))
       .andExpect(status().isOk());
}

@Test
void wrongScopeGets403() throws Exception {
    mvc.perform(get("/api/orders").with(jwt().authorities(new SimpleGrantedAuthority("SCOPE_other"))))
       .andExpect(status().isForbidden());
}

Custom users and method security

@Test
@WithUserDetails(value = "admin@example.com", userDetailsServiceBeanName = "dbUserDetailsService")   // loads a real user from your service
void withRealUser() { }

@SpringBootTest
class DocumentServiceSecurityTest {
    @Autowired DocumentService service;

    @Test
    @WithMockUser(roles = "USER")
    void userCannotDeleteAll() {
        assertThrows(AccessDeniedException.class, () -> service.deleteAll());
    }

    @Test
    @WithMockUser(roles = "ADMIN")
    void adminCanDeleteAll() { service.deleteAll(); }
}

What to test

  • Every endpoint: anonymous (401), wrong role (403), right role (200).
  • Ownership: user A cannot read or change user B's object (IDOR test).
  • Validation of tokens: expired, wrong issuer, wrong audience, bad signature are rejected. Build such tokens in a test with a test key.
  • Headers: assert Content-Security-Policy, X-Frame-Options and Cache-Control on responses.
  • Login lockout, password rules and refresh token rotation with integration tests.
// A test that fails the build if a new endpoint is left open
@Test
void allEndpointsRequireAuthenticationExceptWhitelist() throws Exception {
    for (String path : List.of("/api/orders", "/api/users", "/api/products/1")) {
        mvc.perform(get(path)).andExpect(status().isUnauthorized());
    }
}

Common mistake: Testing only the happy path with @WithMockUser(roles = ADMIN). Security bugs live in the negative cases: no login, wrong role, another user's data, expired tokens. Write those tests first.

Interview questions

What does @WithMockUser do?

It puts a fake authenticated user with the given roles into the SecurityContext for the test. It skips login and password checks.

Why must I add with(csrf()) in POST tests?

CSRF protection is active in tests too. Without a token, POST, PUT and DELETE return 403.

How do I test JWT validation rules?

Create tokens with a test key in the test (expired, wrong audience) and send them to a running app or a JwtDecoder built with the same validators, and assert they are rejected.

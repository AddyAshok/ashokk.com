Security Architecture: FilterChainProxy, SecurityContext and AuthenticationManager

These are the core building blocks that appear in every stack trace and every customization. Each component has one job, and once you know them, security code becomes predictable.

Component map

┌───────────────────────────── one request ───────────────────────────────┐
│ DelegatingFilterProxy ─► FilterChainProxy ─► SecurityFilterChain #1 (/api/**)    │
│                                          └─► SecurityFilterChain #2 (/**)       │
│                                                                                 │
│ inside a chain:                                                                 │
│  AuthenticationFilter ──creates──► Authentication (unauthenticated)             │
│        │                                                                        │
│        ▼                                                                        │
│  AuthenticationManager (interface)                                              │
│        └─ ProviderManager (implementation) ─ loops over ─►                      │
│               AuthenticationProvider  (DaoAuthenticationProvider, JwtAuth...)   │
│                    ├─ UserDetailsService ─► UserDetails                         │
│                    └─ PasswordEncoder                                           │
│        ▼                                                                        │
│  Authentication (authenticated, with authorities)                               │
│        ▼                                                                        │
│  SecurityContextHolder ─► SecurityContext ─► Authentication   (ThreadLocal)     │
│        ▼                                                                        │
│  AuthorizationFilter ─► AuthorizationManager  (decides allow or deny)           │
└─────────────────────────────────────────────────────────────────────────────────┘
ComponentJob
DelegatingFilterProxyA servlet Filter that forwards to a Spring bean, so Spring beans can act as servlet filters
FilterChainProxyThe bean that owns all SecurityFilterChains, picks the first whose RequestMatcher matches, adds firewall checks (StrictHttpFirewall rejects // ; %2e encoded tricks)
SecurityFilterChainA RequestMatcher plus an ordered list of Filters
AuthenticationThe token object: principal (who), credentials (proof), authorities (permissions), authenticated flag, details
AuthenticationManagerauthenticate(Authentication): returns a fully authenticated object or throws AuthenticationException
ProviderManagerDefault AuthenticationManager. Tries each AuthenticationProvider that supports() the token type, and can have a parent
AuthenticationProviderKnows how to verify one kind of credentials (password, JWT, OTP, LDAP)
UserDetailsServiceLoads user data by username: loadUserByUsername
PasswordEncoderencode() for storing, matches() for checking, upgradeEncoding() for migration
SecurityContextHolderStores the SecurityContext for the current thread (default strategy MODE_THREADLOCAL)
GrantedAuthorityOne permission or role as a string (ROLE_ADMIN, orders:read)
AuthorizationManagercheck(Supplier<Authentication>, object): AuthorizationDecision. Used for URLs and methods

The Authentication object

// BEFORE authentication (created by a filter)
Authentication token = UsernamePasswordAuthenticationToken.unauthenticated("ram", "ram123");
token.isAuthenticated();                         // false

// AFTER authentication (created by the provider)
Authentication result = authenticationManager.authenticate(token);
result.getPrincipal();                           // UserDetails (or a String or a Jwt)
result.getCredentials();                         // null: credentials are erased after success
result.getAuthorities();                         // [ROLE_USER]
result.isAuthenticated();                        // true

ProviderManager algorithm

authenticate(token)
  for each provider in providers:
      if !provider.supports(token.getClass())   continue           ← e.g. Dao supports UsernamePassword..., Jwt supports BearerTokenAuthenticationToken
      try   result = provider.authenticate(token)
            if result != null ─► copy details, ERASE credentials, publish AuthenticationSuccessEvent ─► return result
      catch AccountStatusException / InternalAuthenticationServiceException ─► rethrow at once
      catch AuthenticationException ─► remember it, try the next provider
  if nothing succeeded: ask the parent AuthenticationManager (if any), else throw the remembered exception (ProviderNotFoundException if none supported)

What the DaoAuthenticationProvider does

authenticate(UsernamePasswordAuthenticationToken)
  1. user = UserDetailsService.loadUserByUsername(name)    (not found ─► UsernameNotFoundException, hidden as BadCredentials)
  2. preAuthenticationChecks:  isAccountNonLocked / isEnabled / isAccountNonExpired    ─► LockedException, DisabledException, AccountExpiredException
  3. additionalAuthenticationChecks: passwordEncoder.matches(rawPassword, user.getPassword())  ─► BadCredentialsException
  4. postAuthenticationChecks: isCredentialsNonExpired                                        ─► CredentialsExpiredException
  5. if passwordEncoder.upgradeEncoding(hash) ─► re-encode and save (UserDetailsPasswordService)
  6. return a NEW authenticated token with the user's authorities
  (a dummy password check is done even for unknown users, to reduce timing attacks)

SecurityContextHolder: where the current user lives

Authentication auth = SecurityContextHolder.getContext().getAuthentication();
String name = auth.getName();

// set it manually (for example in a custom filter or a test)
SecurityContext context = SecurityContextHolder.createEmptyContext();
context.setAuthentication(new UsernamePasswordAuthenticationToken("job-runner", null, List.of(new SimpleGrantedAuthority("ROLE_SYSTEM"))));
SecurityContextHolder.setContext(context);

// strategies: MODE_THREADLOCAL (default), MODE_INHERITABLETHREADLOCAL, MODE_GLOBAL
// New threads (@Async, executors) do NOT see the context unless you delegate it:
Executor delegating = new DelegatingSecurityContextExecutor(Executors.newFixedThreadPool(4));

A ThreadLocal context is cleared at the end of every request by SecurityContextHolderFilter. This is why a request never sees the user of another request that used the same thread from the pool.

The firewall

Before any filter runs, FilterChainProxy applies StrictHttpFirewall. It rejects suspicious requests with RequestRejectedException: encoded slashes, double slashes, semicolons in paths, backslashes, null bytes, and disallowed HTTP methods. This blocks many path traversal and URL matching bypass attempts. Change it only with a very good reason.

Common mistake: Building your own AuthenticationManager or Authentication handling in a controller (reading the password yourself and comparing). Use the framework pipeline. Hand-written login code misses timing protection, events, lockout hooks and password upgrade.

Interview questions

Difference between AuthenticationManager and AuthenticationProvider?

AuthenticationManager is the entry API. ProviderManager implements it and delegates to a list of AuthenticationProviders, each supporting one type of credentials.

Why are credentials null after authentication?

ProviderManager erases credentials after success (eraseCredentialsAfterAuthentication) so that passwords do not stay in memory or in the session.

Why does the security context disappear in @Async methods?

It is stored in a ThreadLocal that belongs to the request thread. Use DelegatingSecurityContextExecutor or a task decorator to copy it.

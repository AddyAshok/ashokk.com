OAuth 2.0 and OpenID Connect Concepts

OAuth 2.0 is the standard for delegated authorization, and OpenID Connect (OIDC) adds authentication (login) on top. Modern systems use them for single sign-on, social login and API access tokens. Understand the roles, the flows and the tokens before you write configuration.

Roles

RoleMeaningExample
Resource OwnerThe user who owns the dataYou
ClientThe application that wants accessA React app, your Spring Boot web app, a mobile app
Authorization ServerAuthenticates the user and issues tokensKeycloak, Auth0, Okta, Azure AD, Google, Spring Authorization Server
Resource ServerThe API that accepts access tokensYour Spring Boot REST API

Tokens

TokenForFormatLifetime
Access tokenCalling the API (Bearer)JWT or opaqueMinutes
Refresh tokenGetting a new access tokenOpaqueHours to days
ID token (OIDC)Proves who the user is to the CLIENTJWTMinutes. Never send it to an API as an access token

Authorization Code flow with PKCE (the recommended flow)

User        Client (SPA / mobile / web app)        Authorization Server           Resource Server (API)
 │   click login        │                                       │                              │
 │─────────────────────►│ 1. create code_verifier (random), code_challenge = SHA256(verifier)  │
 │                      │ 2. redirect browser: /authorize?response_type=code&client_id&redirect_uri&scope&state&code_challenge
 │◄─────────────────────┴──────────────────────────────────────►│
 │ 3. user logs in at the authorization server, gives consent    │
 │◄──────────────────────────────── redirect to redirect_uri?code=XYZ&state=... ───────────►│ client
 │                      │ 4. POST /token  code=XYZ & code_verifier   (PKCE proof)               │
 │                      │◄───────────────────────────── access_token, refresh_token, id_token ──┤
 │                      │ 5. GET /api/orders  Authorization: Bearer <access_token> ────────────────────────►│
 │                      │                                        6. verify signature, exp, iss, aud, scope   │
 │                      │◄──────────────────────────────────────────────────────── 200 JSON ───────────────┤
  • PKCE (Proof Key for Code Exchange) protects the code: even if an attacker steals it, they lack the code_verifier. Use PKCE for ALL public clients (SPAs, mobile) and also for confidential clients.
  • state is a random value that protects against CSRF on the redirect.
  • The client never sees the user's password. The user types it only at the authorization server.

Scopes and claims

A scope is a permission string the client asks for (read:orders, profile, email). The access token contains the granted scopes. In Spring Security they become authorities with the prefix SCOPE_ (hasAuthority('SCOPE_read:orders')). OIDC adds standard scopes: openid, profile, email, offline_access.

OAuth2 or a simple JWT login of my own?

QuestionOwn JWT loginOAuth2 / OIDC with an identity provider
EffortYou build login, registration, password reset, MFA, refresh, revocationThe identity provider does it
SSO across appsHardBuilt in
Social login, MFA, brute-force protectionYou build itProvided
Risk of mistakesHighLower (well-tested product)
Control and costFull control, no licenseDepends on the product (Keycloak is free and self-hosted)

For a serious system prefer an identity provider (Keycloak, Auth0, Okta, Azure AD) and make your Spring Boot application a resource server. Build your own token issuing only for small internal apps or for learning.

Common mistake: Using the OAuth2 password grant or the implicit flow because tutorials show them. Both are deprecated and unsafe. Use Authorization Code with PKCE for users and Client Credentials for services.

Interview questions

What is the difference between OAuth2 and OIDC?

OAuth2 is about authorization: getting access to resources. OIDC is a layer on top of it that adds login: the ID token and standard user information.

What is PKCE and why is it needed?

A proof mechanism: the client sends a hash of a secret with the authorization request and the secret with the token request. A stolen authorization code is useless without it. It is required for public clients.

Can I use the ID token to call my API?

No. The ID token is for the client to learn who the user is. APIs must accept only access tokens with the right audience and scopes.

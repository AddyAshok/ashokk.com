OAuth2 Login and Keycloak with Spring Boot

Two typical setups: a web application that lets users log in with an external provider (oauth2Login), and an API that trusts tokens issued by Keycloak (resource server) with role mapping.

Setup A: Login with Google or GitHub (oauth2Login)

<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-oauth2-client</artifactId>
</dependency>
spring:
  security:
    oauth2:
      client:
        registration:
          google:
            client-id: ${GOOGLE_CLIENT_ID}
            client-secret: ${GOOGLE_CLIENT_SECRET}
            scope: openid, profile, email
          github:
            client-id: ${GITHUB_CLIENT_ID}
            client-secret: ${GITHUB_CLIENT_SECRET}
@Bean
SecurityFilterChain chain(HttpSecurity http) throws Exception {
    http.authorizeHttpRequests(a -> a.requestMatchers("/", "/error").permitAll().anyRequest().authenticated())
        .oauth2Login(Customizer.withDefaults())                              // adds /oauth2/authorization/google and the redirect handling
        .logout(l -> l.logoutSuccessUrl("/"));
    return http.build();
}

@RestController
class ProfileController {
    @GetMapping("/profile")
    Map<String, Object> profile(@AuthenticationPrincipal OidcUser user) {    // for GitHub (plain OAuth2) use OAuth2User
        return Map.of("name", user.getFullName(), "email", user.getEmail());
    }
}
Browser ─► /oauth2/authorization/google
        ─► OAuth2AuthorizationRequestRedirectFilter: redirect to Google (code flow, state, nonce)
        ─► Google login ─► redirect to /login/oauth2/code/google?code=...
        ─► OAuth2LoginAuthenticationFilter: exchange the code for tokens, verify the ID token, load user info
        ─► OidcUser stored in the session (normal session security afterwards)

Redirect URI to register at the provider: {baseUrl}/login/oauth2/code/{registrationId}, for example http://localhost:8080/login/oauth2/code/google.

Setup B: API protected by Keycloak (resource server)

docker run -d --name keycloak -p 8180:8080 -e KC_BOOTSTRAP_ADMIN_USERNAME=admin -e KC_BOOTSTRAP_ADMIN_PASSWORD=admin \
  quay.io/keycloak/keycloak:latest start-dev
# admin console: http://localhost:8180  -> create realm "shop", client "shop-frontend" (public, PKCE), roles USER and ADMIN, users
spring:
  security:
    oauth2:
      resourceserver:
        jwt:
          issuer-uri: http://localhost:8180/realms/shop        # Spring downloads the public keys (JWKS) from here
@Configuration
@EnableWebSecurity
@EnableMethodSecurity
public class ApiSecurityConfig {

    @Bean
    SecurityFilterChain api(HttpSecurity http) throws Exception {
        http.csrf(csrf -> csrf.disable())
            .sessionManagement(s -> s.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
            .authorizeHttpRequests(a -> a
                .requestMatchers("/actuator/health").permitAll()
                .requestMatchers("/api/admin/**").hasRole("ADMIN")
                .anyRequest().authenticated())
            .oauth2ResourceServer(o -> o.jwt(j -> j.jwtAuthenticationConverter(keycloakConverter())));
        return http.build();
    }

    // Keycloak puts realm roles in the claim realm_access.roles
    private JwtAuthenticationConverter keycloakConverter() {
        JwtAuthenticationConverter converter = new JwtAuthenticationConverter();
        converter.setJwtGrantedAuthoritiesConverter(jwt -> {
            Map<String, Object> realmAccess = jwt.getClaimAsMap("realm_access");
            Collection<String> roles = realmAccess == null ? List.of() : (Collection<String>) realmAccess.getOrDefault("roles", List.of());
            return roles.stream().map(r -> (GrantedAuthority) new SimpleGrantedAuthority("ROLE_" + r.toUpperCase())).toList();
        });
        return converter;
    }
}
# get a token for testing (direct access grant enabled on a TEST client only)
curl -s -d "client_id=shop-test" -d "username=ram" -d "password=ram123" -d "grant_type=password" \
  http://localhost:8180/realms/shop/protocol/openid-connect/token
curl -H "Authorization: Bearer <access_token>" http://localhost:8080/api/orders

What the resource server validates on every request

  • Signature with the public key from the JWKS endpoint (cached, refreshed when an unknown kid appears).
  • exp and nbf (time), iss (issuer equals issuer-uri).
  • Add an audience check: your API must only accept tokens meant for it (see the JWT hardening page).
  • No call to Keycloak is needed per request. That is why JWT scales, and also why revocation is not immediate.

Machine to machine: client credentials

spring:
  security:
    oauth2:
      client:
        registration:
          billing:
            provider: keycloak
            client-id: order-service
            client-secret: ${ORDER_SERVICE_SECRET}
            authorization-grant-type: client_credentials
            scope: billing.write
        provider:
          keycloak:
            token-uri: http://localhost:8180/realms/shop/protocol/openid-connect/token

With the OAuth2 client support, RestClient or WebClient can obtain and refresh a token automatically and add it to outgoing calls.

Common mistake: Enabling the direct access (password) grant in the production Keycloak client to make testing easy. Use it only in a separate test client and use Authorization Code with PKCE for real users.

Interview questions

How does the API know a token is valid without calling Keycloak?

It verifies the JWT signature with Keycloak's public key (JWKS), and checks expiry, issuer and audience. Keys are cached.

Why are my roles missing in Spring Security?

By default only the scope claim becomes SCOPE_ authorities. Keycloak roles live in realm_access or resource_access and need a custom JwtAuthenticationConverter.

Where do users log in when I use Keycloak?

On the Keycloak login page. Your Spring Boot applications never see the password, only tokens.

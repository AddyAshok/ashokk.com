Custom AuthenticationProvider, Handlers, Events and Account Lockout

When passwords are not the only proof (OTP codes, API secrets, LDAP, external services), you write an AuthenticationProvider. This page also shows success and failure handlers, authentication events, and a complete brute-force lockout design.

Custom provider: password plus one-time code (2FA)

// The token that carries username, password and OTP
public class OtpAuthenticationToken extends AbstractAuthenticationToken {
    private final String username, password, otp;
    private final Object principal;

    public OtpAuthenticationToken(String username, String password, String otp) {   // unauthenticated
        super(null);
        this.username = username; this.password = password; this.otp = otp; this.principal = username;
        setAuthenticated(false);
    }
    public OtpAuthenticationToken(UserDetails user, Collection<? extends GrantedAuthority> authorities) {   // authenticated
        super(authorities);
        this.username = user.getUsername(); this.password = null; this.otp = null; this.principal = user;
        setAuthenticated(true);
    }
    public String getUsername() { return username; }
    public String getPassword() { return password; }
    public String getOtp() { return otp; }
    @Override public Object getCredentials() { return password; }
    @Override public Object getPrincipal() { return principal; }
}

@Component
public class OtpAuthenticationProvider implements AuthenticationProvider {

    private final UserDetailsService users;
    private final PasswordEncoder encoder;
    private final OtpService otpService;

    public OtpAuthenticationProvider(UserDetailsService users, PasswordEncoder encoder, OtpService otpService) {
        this.users = users; this.encoder = encoder; this.otpService = otpService;
    }

    @Override
    public Authentication authenticate(Authentication authentication) throws AuthenticationException {
        OtpAuthenticationToken token = (OtpAuthenticationToken) authentication;
        UserDetails user;
        try { user = users.loadUserByUsername(token.getUsername()); }
        catch (UsernameNotFoundException e) { throw new BadCredentialsException("Invalid credentials"); }   // hide which part failed

        if (!encoder.matches(token.getPassword(), user.getPassword())) throw new BadCredentialsException("Invalid credentials");
        if (!user.isEnabled()) throw new DisabledException("Account disabled");
        if (!otpService.verify(user.getUsername(), token.getOtp())) throw new BadCredentialsException("Invalid credentials");

        return new OtpAuthenticationToken(user, user.getAuthorities());
    }

    @Override
    public boolean supports(Class<?> type) { return OtpAuthenticationToken.class.isAssignableFrom(type); }   // which tokens I handle
}
// Register: ProviderManager collects all AuthenticationProvider beans automatically when you build the manager yourself
@Bean
AuthenticationManager authenticationManager(OtpAuthenticationProvider otpProvider, DaoAuthenticationProvider dao) {
    return new ProviderManager(otpProvider, dao);
}

@RestController
class LoginController {
    private final AuthenticationManager manager;
    LoginController(AuthenticationManager manager) { this.manager = manager; }

    @PostMapping("/login-otp")
    Map<String, String> login(@RequestBody OtpLogin req) {
        Authentication result = manager.authenticate(new OtpAuthenticationToken(req.username(), req.password(), req.otp()));
        SecurityContextHolder.getContext().setAuthentication(result);
        return Map.of("user", result.getName());
    }
    record OtpLogin(String username, String password, String otp) { }
}

Authentication events: audit and lockout

@Component
public class AuthEventListener {
    private static final Logger log = LoggerFactory.getLogger("SECURITY_AUDIT");
    private final LoginAttemptService attempts;
    public AuthEventListener(LoginAttemptService attempts) { this.attempts = attempts; }

    @EventListener
    public void onSuccess(AuthenticationSuccessEvent event) {
        String user = event.getAuthentication().getName();
        attempts.reset(user);
        log.info("LOGIN_SUCCESS user={}", user);
    }

    @EventListener
    public void onFailure(AbstractAuthenticationFailureEvent event) {
        String user = String.valueOf(event.getAuthentication().getPrincipal());
        attempts.recordFailure(user);
        log.warn("LOGIN_FAILURE user={} reason={}", user, event.getException().getClass().getSimpleName());
    }
}

Complete brute-force protection: lockout with expiry

login attempt ─► failed ─► counter for user (and for IP) +1  (stored in Redis or DB with TTL)
                 ─► counter >= 5 ─► account is locked for 15 minutes  (isAccountNonLocked() = false ─► LockedException)
   successful login ─► counter is reset
Also: rate limit per IP, add growing delay, notify the owner by email, and never reveal whether the account exists.
@Service
public class LoginAttemptService {

    private static final int MAX_ATTEMPTS = 5;
    private static final Duration LOCK_TIME = Duration.ofMinutes(15);
    private final StringRedisTemplate redis;

    public LoginAttemptService(StringRedisTemplate redis) { this.redis = redis; }

    public void recordFailure(String username) {
        String key = "login:fail:" + username.toLowerCase();
        Long count = redis.opsForValue().increment(key);
        if (count != null && count == 1) redis.expire(key, LOCK_TIME);                 // window starts at the first failure
    }
    public void reset(String username) { redis.delete("login:fail:" + username.toLowerCase()); }

    public boolean isLocked(String username) {
        String v = redis.opsForValue().get("login:fail:" + username.toLowerCase());
        return v != null && Integer.parseInt(v) >= MAX_ATTEMPTS;
    }
}

Locking accounts can be abused to lock out real users (denial of service). Combine it with per-IP rate limits, CAPTCHA after several failures, and short lock times.

Common mistake: Returning different messages for unknown user and wrong password ('user not found' vs 'wrong password'). It tells attackers which emails are registered. Use one generic message and constant-time style checks.

Interview questions

Where do I register a custom AuthenticationProvider?

Declare it as a bean. If it is the only AuthenticationProvider bean, Spring Security uses it. To combine several, build a ProviderManager yourself or use http.authenticationProvider(provider).

What is the difference between AuthenticationException and AccessDeniedException?

AuthenticationException means identity could not be proven (401). AccessDeniedException means identity is known but the action is not permitted (403).

How do I add 2FA?

Either a custom provider that also checks a TOTP code (as shown), or a two-step flow where the first step returns a limited 'pre-auth' state and the second step verifies the code before a full login is granted.

Users, UserDetailsService and Password Encoding

Where users are stored and how passwords are hashed decide how safe your system is when the database leaks. This page covers UserDetails, database users, every PasswordEncoder, the delegating format and safe migration between algorithms.

UserDetails and UserDetailsService

public interface UserDetails extends Serializable {
    Collection<? extends GrantedAuthority> getAuthorities();
    String getPassword();
    String getUsername();
    boolean isAccountNonExpired();
    boolean isAccountNonLocked();
    boolean isCredentialsNonExpired();
    boolean isEnabled();
}
public interface UserDetailsService {
    UserDetails loadUserByUsername(String username) throws UsernameNotFoundException;
}

Users stored with JPA

@Entity
@Table(name = "app_users", uniqueConstraints = @UniqueConstraint(columnNames = "email"))
public class AppUser {
    @Id @GeneratedValue(strategy = GenerationType.IDENTITY) private Long id;
    @Column(nullable = false) private String email;
    @Column(nullable = false) private String passwordHash;
    private boolean enabled = true;
    private boolean locked = false;
    @ElementCollection(fetch = FetchType.EAGER)
    @Enumerated(EnumType.STRING)
    private Set<Role> roles = new HashSet<>();
    // getters, setters
}
public enum Role { USER, MANAGER, ADMIN }

public interface AppUserRepository extends JpaRepository<AppUser, Long> {
    Optional<AppUser> findByEmailIgnoreCase(String email);
}

@Service
public class DbUserDetailsService implements UserDetailsService {

    private final AppUserRepository users;
    public DbUserDetailsService(AppUserRepository users) { this.users = users; }

    @Override
    @Transactional(readOnly = true)
    public UserDetails loadUserByUsername(String email) {
        AppUser u = users.findByEmailIgnoreCase(email)
                .orElseThrow(() -> new UsernameNotFoundException("User not found"));   // same message for all failures
        return User.builder()
                .username(u.getEmail())
                .password(u.getPasswordHash())
                .disabled(!u.isEnabled())
                .accountLocked(u.isLocked())
                .authorities(u.getRoles().stream().map(r -> new SimpleGrantedAuthority("ROLE_" + r.name())).toList())
                .build();
    }
}

Password hashing: why and how

  • Never store plain text and never use fast hashes (MD5, SHA-1, SHA-256 alone) for passwords. Attackers test billions of guesses per second on a GPU.
  • A password hash must be slow on purpose (adaptive work factor) and salted (random value per password), so the same password gives different hashes and rainbow tables are useless.
  • Spring Security's encoders generate the salt and store it inside the hash string.

PasswordEncoder bcrypt = new BCryptPasswordEncoder(12);          // each +1 doubles the time
String hash = bcrypt.encode("MySecret#1");
// $2a$12$Xw5c3...   = version, cost, 22 chars salt, 31 chars hash
boolean ok = bcrypt.matches("MySecret#1", hash);                  // true

PasswordEncoder argon = Argon2PasswordEncoder.defaultsForSpringSecurity_v5_8();

Choose the cost so that one hash takes about 100 to 300 ms on your production hardware. Too low is weak, too high makes login a denial of service target.

DelegatingPasswordEncoder: the {id} format

{bcrypt}$2a$10$dXJ3SW6G7P50lGmMkkmwe.20cQQubK3.HZWzG3YB1tlRy.fqvM/BG
{argon2}$argon2id$v=19$m=16384,t=2,p=1$...
{noop}plain-text-password-for-tests
{pbkdf2}5d923b44a6d129f3ddf3e3c8d29412723dcbde72445e8ef6bf3b508fbf46c8c2....

The prefix says which algorithm created the hash. The delegating encoder reads the prefix and picks the matching encoder, and new passwords use the default (bcrypt). This lets you change algorithms later without a big-bang migration.

@Bean
PasswordEncoder passwordEncoder() {
    // the default is bcrypt. Make argon2 the default for NEW passwords while old hashes keep working
    Map<String, PasswordEncoder> encoders = new HashMap<>();
    encoders.put("argon2", Argon2PasswordEncoder.defaultsForSpringSecurity_v5_8());
    encoders.put("bcrypt", new BCryptPasswordEncoder());
    DelegatingPasswordEncoder delegating = new DelegatingPasswordEncoder("argon2", encoders);
    return delegating;
}

Upgrade hashes automatically at login

@Service
public class DbUserDetailsService implements UserDetailsService, UserDetailsPasswordService {
    // loadUserByUsername as before ...

    @Override
    @Transactional
    public UserDetails updatePassword(UserDetails user, String newEncodedPassword) {
        AppUser u = users.findByEmailIgnoreCase(user.getUsername()).orElseThrow();
        u.setPasswordHash(newEncodedPassword);        // called when encoder.upgradeEncoding(oldHash) is true
        return User.withUserDetails(user).password(newEncodedPassword).build();
    }
}
// DaoAuthenticationProvider calls updatePassword after a successful login when the stored hash uses an outdated algorithm or cost.

Registration and password rules

@Service
public class RegistrationService {
    private final AppUserRepository users;
    private final PasswordEncoder encoder;
    public RegistrationService(AppUserRepository users, PasswordEncoder encoder) { this.users = users; this.encoder = encoder; }

    @Transactional
    public void register(String email, String rawPassword) {
        if (rawPassword.length() < 12) throw new IllegalArgumentException("Password must have at least 12 characters");
        if (users.findByEmailIgnoreCase(email).isPresent()) throw new ConflictException("Email already registered");
        AppUser u = new AppUser();
        u.setEmail(email.toLowerCase());
        u.setPasswordHash(encoder.encode(rawPassword));      // never keep or log the raw password
        u.getRoles().add(Role.USER);
        users.save(u);
    }
}
  • Length beats complexity: require at least 12 characters, allow long passphrases, and check against lists of breached passwords.
  • Do not truncate or restrict characters. Note bcrypt uses only the first 72 bytes.
  • Use the same error message for unknown user and wrong password, and add rate limiting, so attackers cannot find valid accounts.
  • Never send passwords by email. Password reset should use a random, single-use, short-lived token that is stored hashed.

Common mistake: Using SHA-256 or MD5 for passwords because they are 'secure hashes'. They are designed to be fast. Use bcrypt, Argon2, scrypt or PBKDF2 through PasswordEncoder.

Interview questions

Why does the same password give different bcrypt hashes?

bcrypt generates a random salt for each hash and stores it inside the hash string. matches() reads the salt from the stored hash to check the password.

What does {noop} mean?

It is the delegating encoder prefix for plain text (NoOpPasswordEncoder). It exists only for demos and tests.

How do I migrate from MD5 to bcrypt without asking users to reset passwords?

Wrap old hashes as bcrypt(md5) or mark them with a legacy {id}, verify with the old algorithm at login, and immediately re-encode with the new algorithm using UserDetailsPasswordService.

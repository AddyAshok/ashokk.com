Starters and Dependency Management

A starter is a single dependency that pulls in everything you need for one feature, with versions that are tested together. Spring Boot manages the versions of hundreds of libraries for you through a Bill of Materials (BOM).

Common starters

Starter (Boot 3.x names)Gives you
spring-boot-starter-webSpring MVC, embedded Tomcat, Jackson (Boot 4 name: spring-boot-starter-webmvc)
spring-boot-starter-webfluxReactive web with Netty
spring-boot-starter-data-jpaSpring Data JPA, Hibernate, HikariCP
spring-boot-starter-data-jdbc / jdbcJDBC with JdbcTemplate and Hikari
spring-boot-starter-data-mongodb / redisMongoDB and Redis support
spring-boot-starter-securitySpring Security
spring-boot-starter-oauth2-resource-serverJWT and OAuth2 resource server
spring-boot-starter-validationBean Validation (Hibernate Validator)
spring-boot-starter-actuatorHealth, metrics and management endpoints
spring-boot-starter-thymeleafServer-side HTML templates
spring-boot-starter-cache / mail / aopCaching, email sending, AOP
spring-boot-starter-testJUnit 5, Mockito, AssertJ, MockMvc, JsonPath

What spring-boot-starter-parent gives you

  • Default Java version and UTF-8 encoding.
  • Dependency management: versions for hundreds of libraries, so you write no version numbers.
  • Sensible plugin configuration (compiler, resources, repackage).
  • Property based overriding of versions.

Override a version

<properties>
    <java.version>21</java.version>
    <postgresql.version>42.7.4</postgresql.version>   <!-- override the managed version -->
</properties>

If you cannot use the parent: import the BOM

<dependencyManagement>
    <dependencies>
        <dependency>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-dependencies</artifactId>
            <version>3.5.10</version>
            <type>pom</type>
            <scope>import</scope>
        </dependency>
    </dependencies>
</dependencyManagement>

Gradle version

plugins {
    id 'java'
    id 'org.springframework.boot' version '3.5.10'
    id 'io.spring.dependency-management' version '1.1.7'
}

dependencies {
    implementation 'org.springframework.boot:spring-boot-starter-web'
    testImplementation 'org.springframework.boot:spring-boot-starter-test'
}

Switch the embedded server from Tomcat to Jetty

<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-web</artifactId>
    <exclusions>
        <exclusion>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-starter-tomcat</artifactId>
        </exclusion>
    </exclusions>
</dependency>
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-jetty</artifactId>
</dependency>

See the dependency tree

./mvnw dependency:tree
./gradlew dependencies

Common mistake: Writing version numbers for libraries that Spring Boot already manages. This can create version conflicts. Remove the version and let the BOM decide, or override it with a property.

Interview questions

What is the difference between a starter and a normal library?

A starter has almost no code. It is a pom that brings a group of compatible libraries, and auto-configuration then wires them.

How do I write my own starter?

Create an autoconfigure module with the auto-configuration and the imports file, and a starter module named xyz-spring-boot-starter that depends on it.

Why do I get a version conflict?

Usually because a version is set manually. Check with dependency:tree and remove the manual version.

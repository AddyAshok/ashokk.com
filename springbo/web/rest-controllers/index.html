REST Controllers

A REST controller receives HTTP requests, calls your service layer and returns data (usually JSON). Spring Boot converts Java objects to JSON and back automatically.

Mapping annotations

AnnotationHTTP methodTypical use
@GetMappingGETRead data
@PostMappingPOSTCreate data
@PutMappingPUTReplace data
@PatchMappingPATCHChange part of data
@DeleteMappingDELETEDelete data
@RequestMappingAnyClass-level base path

Complete controller

import java.net.URI;
import java.util.*;
import java.util.concurrent.atomic.AtomicLong;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.*;
import org.springframework.web.servlet.support.ServletUriComponentsBuilder;

public record Product(Long id, String name, double price) { }

@RestController
@RequestMapping("/api/products")
public class ProductController {

    private final Map<Long, Product> store = new LinkedHashMap<>();
    private final AtomicLong ids = new AtomicLong();

    @GetMapping                                            // GET /api/products?minPrice=10
    public List<Product> list(@RequestParam(defaultValue = "0") double minPrice) {
        return store.values().stream().filter(p -> p.price() >= minPrice).toList();
    }

    @GetMapping("/{id}")                                   // GET /api/products/5
    public ResponseEntity<Product> get(@PathVariable Long id) {
        Product p = store.get(id);
        return p == null ? ResponseEntity.notFound().build() : ResponseEntity.ok(p);
    }

    @PostMapping                                           // POST /api/products  (JSON body)
    public ResponseEntity<Product> create(@RequestBody Product input) {
        Product saved = new Product(ids.incrementAndGet(), input.name(), input.price());
        store.put(saved.id(), saved);
        URI location = ServletUriComponentsBuilder.fromCurrentRequest()
                .path("/{id}").buildAndExpand(saved.id()).toUri();
        return ResponseEntity.created(location).body(saved);   // 201 + Location header
    }

    @PutMapping("/{id}")
    public ResponseEntity<Product> update(@PathVariable Long id, @RequestBody Product input) {
        if (!store.containsKey(id)) return ResponseEntity.notFound().build();
        Product updated = new Product(id, input.name(), input.price());
        store.put(id, updated);
        return ResponseEntity.ok(updated);
    }

    @DeleteMapping("/{id}")
    public ResponseEntity<Void> delete(@PathVariable Long id) {
        return store.remove(id) == null ? ResponseEntity.notFound().build() : ResponseEntity.noContent().build();
    }
}

Other request features

  • @RequestHeader reads a header, @CookieValue reads a cookie.
  • @RequestMapping(produces = 'application/json', consumes = 'application/json') restricts media types.
  • Pageable parameter: /api/products?page=0&size=10&sort=price,desc works with Spring Data.
  • @ResponseStatus(HttpStatus.CREATED) sets a fixed status.
  • Spring Framework 7 (Boot 4) adds built-in API versioning support for paths, headers and parameters.

Common mistake: Returning entities directly from controllers. It exposes your database structure and can trigger lazy loading errors. Return DTOs (records) instead.

Interview questions

What is the difference between @Controller and @RestController?

@RestController adds @ResponseBody to every method, so return values are written to the response body (JSON) instead of being treated as view names.

What is the difference between PUT and PATCH?

PUT replaces the whole resource. PATCH changes only some fields.

@RequestParam or @PathVariable?

@PathVariable reads a part of the URL path (/products/5). @RequestParam reads a query parameter (?page=2).

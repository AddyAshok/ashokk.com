Caching, Scheduling and Async

Three features that improve performance and automate work: cache repeated results, run tasks on a timer, and run slow work on another thread. All three are proxy-based, so they follow the same rules as @Transactional.

Caching

@Configuration
@EnableCaching
public class CacheConfig { }

@Service
public class ProductLookupService {

    @Cacheable(cacheNames = "products", key = "#id")
    public Product findProduct(Long id) {
        System.out.println("Loading from database: " + id);       // printed only on a cache miss
        return repository.findById(id).orElseThrow();
    }

    @CachePut(cacheNames = "products", key = "#result.id")         // update the cache with the result
    public Product update(Product product) { return repository.save(product); }

    @CacheEvict(cacheNames = "products", key = "#id")              // remove one entry
    public void delete(Long id) { repository.deleteById(id); }

    @CacheEvict(cacheNames = "products", allEntries = true)        // clear the cache
    public void clearAll() { }
}
spring.cache.type=caffeine
spring.cache.caffeine.spec=maximumSize=500,expireAfterWrite=10m
  • Default cache is a simple in-memory map without expiry. Use Caffeine (single instance) or Redis (shared by many instances).
  • Return objects must be serializable for Redis.
  • Self-invocation does not trigger the cache, because it is proxy based.
  • Cache data that is read often and changes rarely. Always define an expiry.

Scheduling

@Configuration
@EnableScheduling
public class SchedulingConfig { }

@Component
public class Jobs {

    @Scheduled(fixedRate = 5000)                    // every 5 seconds from the START of the last run
    public void heartbeat() { System.out.println("alive"); }

    @Scheduled(fixedDelay = 10000, initialDelay = 3000)   // 10 seconds AFTER the last run FINISHED
    public void poll() { }

    @Scheduled(cron = "0 0 2 * * *", zone = "Asia/Kolkata")   // every day at 02:00
    public void nightlyReport() { }
}
Cron fieldAllowed values
second0-59
minute0-59
hour0-23
day of month1-31
month1-12
day of week0-7 (0 and 7 are Sunday) or MON-SUN
  • The default scheduler has ONE thread. A long job delays the others. Set spring.task.scheduling.pool.size=5 if you have several jobs.
  • If you run 3 instances of your application, the job runs 3 times. Use a lock such as ShedLock or a scheduler like Quartz for cluster-safe jobs.

Async

@Configuration
@EnableAsync
public class AsyncConfig {
    @Bean
    public Executor taskExecutor() {
        ThreadPoolTaskExecutor ex = new ThreadPoolTaskExecutor();
        ex.setCorePoolSize(4);
        ex.setMaxPoolSize(8);
        ex.setQueueCapacity(100);
        ex.setThreadNamePrefix("async-");
        ex.initialize();
        return ex;
    }
}

@Service
public class NotificationService {

    @Async
    public CompletableFuture<String> sendEmail(String to) {
        // slow work runs on an "async-" thread
        return CompletableFuture.completedFuture("sent to " + to);
    }

    @Async
    public void fireAndForget() { /* exceptions are only logged, nobody can catch them */ }
}
  • The method must be called from another bean (proxy rule) and be public.
  • Return void, Future or CompletableFuture. Exceptions of void methods need an AsyncUncaughtExceptionHandler.
  • The transaction and the security context do not move to the new thread automatically.

Application events

public record OrderPlacedEvent(Long orderId) { }

@Service
public class OrderService {
    private final ApplicationEventPublisher publisher;
    public OrderService(ApplicationEventPublisher publisher) { this.publisher = publisher; }

    @Transactional
    public void place(Long id) {
        // save order ...
        publisher.publishEvent(new OrderPlacedEvent(id));
    }
}

@Component
public class OrderListener {
    @TransactionalEventListener(phase = TransactionPhase.AFTER_COMMIT)   // only after a successful commit
    public void on(OrderPlacedEvent event) { System.out.println("Send email for " + event.orderId()); }
}

Common mistake: Caching mutable entities that are changed later or caching without expiry. Users see old data, and memory grows. Cache immutable, frequently read data with a time-to-live.

Interview questions

fixedRate or fixedDelay?

fixedRate starts a run at fixed intervals regardless of the last run. fixedDelay waits the given time after the previous run finished.

Why does @Cacheable not work?

Common reasons: @EnableCaching is missing, the method is called from the same class, the method is private, or the key is different than expected.

Can @Async and @Transactional be combined?

Yes, but the async method starts its own transaction on a new thread. It does not join the caller's transaction.

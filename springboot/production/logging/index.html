Logging

Good logs are your best tool when something fails in production. Spring Boot uses SLF4J with Logback by default, so you can log without any setup.

Log levels

LevelUse for
TRACEVery detailed flow (rarely enabled)
DEBUGDeveloper details, for troubleshooting
INFOImportant business events (default level)
WARNUnexpected but handled situations
ERRORFailures that need attention

Logging in code

import org.slf4j.Logger;
import org.slf4j.LoggerFactory;

@Service
public class OrderService {

    private static final Logger log = LoggerFactory.getLogger(OrderService.class);

    public void place(Long orderId, String user) {
        log.info("Placing order {} for user {}", orderId, user);     // use {} placeholders, not +
        try {
            // work ...
        } catch (Exception ex) {
            log.error("Order {} failed", orderId, ex);               // exception LAST: prints the stack trace
        }
        if (log.isDebugEnabled()) {
            log.debug("Details: {}", expensiveToString());           // avoid costly work when disabled
        }
    }
}

Configuration

logging.level.root=INFO
logging.level.com.example.demo=DEBUG
logging.level.org.hibernate.SQL=DEBUG
logging.level.org.springframework.web=WARN

logging.file.name=logs/app.log
logging.logback.rollingpolicy.max-file-size=10MB
logging.logback.rollingpolicy.max-history=14
logging.pattern.console=%d{HH:mm:ss.SSS} %-5level [%X{requestId}] %logger{36} - %msg%n

Change the level at runtime (Actuator)

curl -X POST localhost:8080/actuator/loggers/com.example.demo \
  -H "Content-Type: application/json" -d '{"configuredLevel":"DEBUG"}'

Advanced: logback-spring.xml with profiles

<configuration>
    <springProfile name="dev">
        <root level="DEBUG"><appender-ref ref="CONSOLE"/></root>
    </springProfile>
    <springProfile name="prod">
        <root level="INFO"><appender-ref ref="CONSOLE"/></root>
    </springProfile>
</configuration>

Use the file name logback-spring.xml (not logback.xml) so Spring can process the springProfile tags.

Structured (JSON) logging

Log tools such as Elasticsearch, Loki and Splunk work best with JSON. Spring Boot 3.4 and newer can write structured logs without extra libraries:

logging.structured.format.console=ecs
# other formats: logstash, gelf

MDC: add context to every log line

MDC.put("userId", "ram");
try {
    log.info("Processing");        // pattern %X{userId} prints ram
} finally {
    MDC.clear();
}
  • Never log passwords, tokens or personal data.
  • Log with meaning: include ids (order id, user id) so you can search.
  • Do not log and rethrow the same exception in every layer. That creates duplicate stack traces. Log once, where you handle it.

Common mistake: Building log messages with string concatenation, for example log.debug('User ' + user). The string is created even when DEBUG is off. Use placeholders.

Interview questions

Which logging framework does Spring Boot use?

SLF4J as the API and Logback as the default implementation.

Why put the exception as the last argument?

SLF4J then prints its stack trace. If you put it inside the message with {}, only toString is printed.

How do I see SQL statements?

Set logging.level.org.hibernate.SQL=DEBUG. Avoid spring.jpa.show-sql in production because it prints to standard output without your log format.
